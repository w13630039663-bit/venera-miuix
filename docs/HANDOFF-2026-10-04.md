### 2.3 收藏域的设计要点

取数链**一步都不新造**：
```
ports.favorites.favorites  (GalleryFavoritesStore 真 StateFlow)
  → GalleryFavorite.toPost(site)
  → GalleryMerge.isDisplayable
  → 墙
```
桌面这一侧此前**消费数 0**（Android 侧那份数据一直在落盘）。

**三种空态念成三句话**，因为它们各自要用户做的事不同：

| 判据 | 屏上念的话 |
|---|---|
| `favorites.isEmpty()` | 「还没有收藏过」 |
| `total > 0 && posts.isEmpty()` | 「收藏里有 N 条，但一张都摆不上屏」+ 逐条成因 |
| 其余 | 墙 |

第二档写成第一档的后果不是难看，是**误导**——用户会以为自己的收藏丢了。

**本屏刻意没有移除/清空按钮**：`GalleryFavorites` 的三枚写动作都在，但 Android 侧的移除入口是
「长按 → 确认弹层」，而桌面**没有弹层宿主**（`Dialog` 系在那批被判负）。
摆一枚"点了就永久删掉且不可撤销"的按钮而没有确认层，是本仓最不该有的形状。
⇒ 缺席如实说：本屏是只读的那一档，写侧等弹层宿主。

### 2.4 搜索域的设计要点

三站并发：`GalleryLegGuard.guard` 包每一腿 → `GallerySearchMerge.interleave` → 墙。
三档缺席**分述**不合并：发不出去 / 没答上 / 被预算挡住。

**预算必须在发车前拦**：放到发车后，站方回 422，而那个错误在翻译层会被归成"搜索失败"
——用户看到的是**错的成因**（站方没坏，是我们自己不发）。

### 2.5 状态栏：三句读数的"主语"问题（最容易做坏的地方）

`DesktopGalleryStatusBar` 是**三面墙共用**的一颗。日榜那三句在收藏语境下**主语不存在**：

| 句 | 日榜 | 收藏为什么不能照抄 | 处理 |
|---|---|---|---|
| 「本次取数 X 前」 | 真发了几笔请求 | 读本机 JSON，一次网都不发 | 换前缀 `LOCAL_READ_LABEL`「本机存档读于」 |
| 「N 站 · 都给内容」 | 几站并发谁出了勤 | 存档是已经躺在本机的，没有谁出勤 | `siteTotal = STATUS_NO_SITE_TALLY(-1)` ⇒ 整条不念 |
| 「每站 N 预算 · 超时缺席」 | 真有站被淘汰 | 收藏屏没有"站"这个动作 | `budgetMs = STATUS_NO_BUDGET_MS(-1)` ⇒ 整条不念 |

空收藏时第二句会念「**0 站 · 都给内容**」——一句话同时宣称零个站和全都给了内容。

**站分布没有因此少讲**，挪到段头「本机存档 N 条 · 摆上屏 M 张 · 某某站 k 张」，
那句的主语是"存档"，在本屏是真读数。

⚠️ **三档都由参数表达，不要新造第二颗状态栏**——同一行要改形状时三面墙各改一次就会分叉
（本仓吃过两回：页脚与 Hero 侧卡讲同一件事、弹层容器两处各养一套）。
⚠️ **反向也钉住了**：日榜那档三处闸都不许用（关掉就是少报）。

## 3. 判据抓到的真 bug（值得学的那一类）

收藏域屏上的计数那一项原本**直接取去重后的键数**：

```kotlin
// 错：unrecognizedSites 是去重后的键
unrecognizedSites.size   // 3 条同坏键的记录 → 念「认不出 1 条」
```

用户实际丢掉 3 条却被告知 1 条，回头数存档时对不上，只会更信不过这面墙。

**修法不是撤掉去重**，而是**加一枚不去重的计数字段**：
```kotlin
unrecognizedSites  = unrecognized.distinct().sorted()  // 键：点名用，用户能去存档里定位
unrecognizedCount  = unrecognized.size                  // 条数：计数用，照实念
```
两枚各有用途，**少任何一枚都会坏**。

> 通则：**去重的"名字"与不去重的"数量"是两件事**。凡"点名 + 计数"并存的读数，
> 都要想清楚每一项取的是哪一枚。

## 4. ⚠️ 判据扫源码这一支的三条固有代价（本项目最贵的教训）

`desktop/` 判据有一支是**扫源码文本**的（只用于"不该存在的东西"）。
它有三个反复踩到的坑，**跨项目通用**：

### 4.1 扫全文会把合法构造点扫红
`main()` 禁造引擎那条第一版扫了整个 `VeneraDesktop.kt`，把**合法的**
`runAutofavEvidence`（`--autofav` 取证链，自带 `finally close` + 退出码判据）判红了。

> **一条把合法点扫红的判据比没有判据更坏**——下一个人只会去删判据或改坏正事。

修法：按**函数体**切（配平数大括号），并补**反向断言**"那一处必须还在"
（否则整条链被删判据照样绿，而功能静默失灵）。

### 4.2 判据的对象是"是什么"不是"在哪"
首卡跨列那条扫 `DesktopDailyPane.kt`。画法提成共用件后它一直红，
而红的原因与它要防的事毫无关系 ⇒ **搬家要认一次红，改判据，别改实现**。
只查"共用件在不在"**也不够**：留着旧 `private` 同名定义时编译器不报错
（不同文件、不同可见性），屏上已经是两套画法 ⇒ 还要断言消费文件里不再有那份定义。

### 4.3 测试 helper 的参数序要按"调用点的默认形状"排
把罕用的形参（要具名传的那个）排在前面，而多数调用点按位置传参
⇒ 一批调用点把 `Long` 喂给 `String` 形参，错误信息指向"测试数据写错"，
真正的原因（参数序）不在现场。

## 7. 官方源码是唯一仲裁者

`.reference/` 下有官方快照。**"源脚本报错但逻辑没问题"时，先怀疑 Dart↔Kotlin 语义差**。

| 目录 | 是什么 |
|---|---|
| `.reference/flutter-master/` | 官方 Flutter/Dart 全量源码（行为口径的最终依据） |
| `.reference/miuix-*-094/` | miuix 各模块（blur/core/shader/ui） |
| `.reference/venera-miuix/` | 官方 Kotlin/Compose 版 |

已知的语义坑（`String(bytes,UTF_8)` 不跳 BOM、jsoup `Element.text` 跳 DataNode、
OkHttp cookie domain 拒前导点、自定义 Accept-Encoding 会拿到 gzip、图片缓存键必须
`"$imageKey@$sourceKey@$cid@$eid"`）都记在 `.workbuddy/memory/MEMORY.md` 的「官方语义是唯一标准」一节。

**注意**：`.reference` 是快照不是活仓库，升级时要重新取。

## 8. ⛔ 验证禁令（用户明确要求，务必遵守）

| 禁令 | 范围 |
|---|---|
| **不许用 adb 自验**（`adb install` / `monkey` / `input tap` / `screencap` / `uiautomator dump` / `logcat`） | Android 端 |
| **不许动鼠标**（`mouse_event` / `SetCursorPos`） | 桌面端。2026-10-04 用户原话：「后台验证就行，不要动鼠标」 |

原因：识别率差（命中区与文字中心不是一回事，靠像素反推会点错域），
且无人值守自截图才是正解。

**agent 侧交到「编译 + 单测 + 出包」为止**，真机验证交回用户。

```bash
# 桌面线编译 + 全量判据
./gradlew :desktop:compileKotlin -q
./gradlew :desktop:test -q
# Android 线基线
./gradlew :app:testDebugUnitTest --rerun-tasks -q
```

⚠️ 后台长任务一律用 `run_in_background=true` + `TaskOutput` 读数。
**`nohup … &` / `cmd &` 的进程组活不过单次调用结束**。
⚠️ Bash 工具里**不许调 powershell**；PowerShell stdout 不稳 ⇒ 写文件再 Read。

## 12. 一号原则（贯穿一切）

**绝不伪造内容。**

- 数据缺失留空，UI 如实降级，新字段默认空/未知。

  念成"这台机器上没有"，后者是假的。

  同等严重。
