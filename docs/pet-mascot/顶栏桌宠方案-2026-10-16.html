先说结论：这个需求有个原生落点

角色应当落在 VeneraTopAppBar 的 navigationIcon 槽位。

该槽位在 miuix 顶栏里是「锚定在 collapsedHeight / 2」的，与折叠进度无关——大标题在它下方折叠，它自己一步都不动。这正是你要的「位置恒定」，且不需要写任何跟随动画。

两条硬约束：
① 顶栏根 Modifier 挂了 clipToBounds()，而 navigationIcon 的高度不参与 barHeight 计算 ⇒ 任何高于 52dp 的元素会被上下对称裁掉（64dp 会被切掉上下各 6dp）。想保留 C 的体量，只能绕开槽位自绘一层，并同步抬高顶栏高度。
② 首页首屏厚度是定过的（历史区正是从两行改单行才不压首屏），顶栏再增高 20dp 会动到 statusBarTop + 104dp 这条全站避让口径。
结论
视觉最抓人，但改动面从「一个 composable」扩到「顶栏布局 + 全站避让」

交互规范

角色是「可点击的陪伴物」，不是按钮。反馈要轻、要短、要不打断阅读。

触发反馈时长落地要点
轻点按压回弹（scale 0.94→1）+ 冒出随机台词气泡180ms / 气泡 2.4s台词池轮换，避免连续重复；气泡从角色右侧展开，不遮标题
连点 3 次切换姿态（眨眼 / 甩尾 / 缩成一团）600ms做冷却，防止误触连发
长按 500ms「摸头」：闭眼 + 脸泛红 + 轻微下沉按住期间维持松手后 300ms 回到待机
空闲 30s打盹：眼半闭 + Zzz 气泡脉动持续到有输入任意触摸 / 滚动即唤醒
业务事件刷新源时跟着转、有源更新时举手示意跟随事件复用首页已有的 refreshPings()、availableUpdates 状态
折叠 / 展开不动（A / B）—这条是需求核心，别加跟随位移
手势冲突提醒：miuix 顶栏在根节点挂了 detectTapGestures { } 抢占空白区点击；VeneraTopAppBar 还会在外层挂双击回顶。子组件的 clickable 会先拿到事件，所以角色的轻点 / 长按都不受影响——这一点与「三颗胶囊照常可点」是同一套机制。另外角色不要在左边缘做 8dp 以内的贴边裁切，否则会压到 Android 的侧滑返回热区。

落地要点

首页调用 VeneraTopAppBar 时 navigationIcon 从前是空的，加一个即可。2026-10-16 落地时现量改数：全仓 VeneraTopAppBar 调用点是 15 处（本句从前写 12），其中 4 处没传 navigationIcon（首页 / 探索 / 收藏 / 图库首页），其余 11 处已各自传了返回钮或源名 —— 所以「零改动」只对那 11 处成立，不是对全部调用点成立。另：本篇从前说「13 个页面共用顶栏」，同一枚旧数。

落地状态（2026-10-16 晚）：走的是裸贴纸 66×39.5dp（下面那段示例代码里的 40dp 圆角徽章是方案 A 的形状，未采用），常驻无限循环，开关在 设置 → 外观与主题 → 首页顶栏 → 桌宠小肥鱼（默认关）。示例代码里的 onClick 那一格没有实现 —— 台词池还不存在，摆一枚按下去没反应的贴纸就是假开关，所以桌宠刻意不可点击。逐批读数见手册 §16 行 207，五套摆法的实测稿在 首页顶栏桌宠摆法稿-2026-10-16.html。

    largeTitle = "首页",
    scrollBehavior = topBarBehavior,
    backdrop = topBarBackdrop,

    actions = { /* 原有三颗胶囊，一行不动 */ },

@Composable
fun PetMascot(onClick: () -> Unit) {
    // 外层 16dp 由 NavigationIconPadding 提供；52dp 行内放得下 48dp 触达盒
    Box(
        Modifier
            .size(48.dp)
            .clip(RoundedCornerShape(12.dp))
            .clickable(role = Role.Button, onClickLabel = "摸摸小肥鱼") { onClick() },
        contentAlignment = Alignment.CenterStart,
    ) {
        Box(Modifier.size(40.dp).clip(RoundedCornerShape(12.dp)).background(tokens.color.surfaceContainer)) {
            Image(painterResource(R.drawable.pet_mascot), contentScale = ContentScale.Crop)
        }
    }
}
  • 尺寸口径：40dp / 12dp 圆角请走 ui/tokens/；新增数值会被 TokenBudgetFrozenTest 记账，别在页面里写裸 dp。
  • 绘制期取色：tokens.* 是 @Composable getter，在 offset{} / drawWithContent{} 里读不到——台词气泡这类动效要在组合期先取好局部量。
  • 只挂首页：13 个页面共用顶栏，桌宠建议只挂在首页（或收敛到一个「桌面伴侣」开关），否则每个页面左上角都冒出一只，会变成噪音。
  • 宽屏档：≥600dp 出现侧栏后，角色应跟随内容区左边缘（contentMaxWidthFor 口径），而不是钉在物理屏幕左边。
  • 无障碍：contentDescription + Role.Button 必填；并让动效尊重系统的「减少动态效果」设置。

除顶栏之外的出场体系

吉祥物该出现在哪，应该由「系统什么时候需要表达情绪」决定，而不是由「哪里还有空地」决定。按出现的理由而不是屏幕位置分五层：

层出现的理由频率
常驻顶栏伴随位（已定，只挂首页）始终
空态代班系统没话说时，让它来说 —— 价值最高事件驱动
等待陪伴系统变慢时陪你等超过 800ms 才现身
仪式时刻值得记住的那一下一天不超过一次
身份签名它是谁的落款静态出现

具体落点

层挂载点触发条件
空态代班components/VeneraEmptyView.kt（20+ 处调用点自动受益）tone = Nothing / NotYet / Failed，三态各配一张脸
空态·分区同上，size = Compact首页分区为空（用缩小版，不要原尺寸）
等待陪伴首页推荐首屏加载 · sourceManager.refreshPings()耗时超过 800ms 才现身；快就不出现，避免闪一下
仪式冷启动（MainActivity → VeneraComposeApp）一天只问候一次
仪式首页「阅读统计 · 连续天数」刷新个人纪录时
仪式availableUpdates 非空有源可更新
身份签名SettingsHome 的自绘 hero 头图区进设置页，静态不互动

建议同时否决的位置

  • 底部导航栏：五个 tab 已经把注意力和触达占满了，再塞一只必然抢戏——而且它和「页面切换」这个动作没有语义关系。
  • 阅读器 / 画廊大图页：沉浸式内容场景，任何常驻元素都是干扰。
  • 身份卡那张 56dp 图位：AboutSection.AppIdentityCard 渲染的是 R.drawable.app_icon，换成角色会跟启动器图标、应用商店展示不一致。
  • VeneraEmptyView 的 Inline 档：它的定义就是「列表里的一行说明，不摆图标」，本来也不需要图。
  • 长列表滚动中途：滚动时出现的东西一定会被当成广告。
真正的瓶颈：姿态只有一张。
现在手上是一张「趴着睡觉」的立绘。上面这些位置至少需要一套姿态语汇才撑得起来——待机 / 邀请（NotYet）/ 抱歉（Failed）/ 发呆（Nothing）/ 睡着（空闲）/ 庆祝（里程碑）/ 探头（等待）。
不想画这么多时，可以用程序化变换顶一部分（缩放、位移、倾斜、局部动效），语义不足的地方交给气泡文字补——但必须保证同一屏里不会出现两个不同位置、同一个姿势，否则「它跟着我」的错觉立刻垮掉。
