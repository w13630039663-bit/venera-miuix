0三句话结论

① 不同水平线 = 我自己上一轮加的盒子
为"恒折叠态"加的 .height(状态栏 + 折叠高) 是 SizeNode：子内容报出来的高度 大于被钉的高度时，它交给父级的是居中而不是顶部对齐 —— miuix 本体被往上顶 18dp。 三条独立证据（含"上一版截图里它还在正位"）指向它，算式与实测都是 18dp。
② 字体小 = 两处都自己挑了一格字号
miuix 给这两格用的是主题槽位（小标题 title3、大标题 title1）， 我们写的是 itemTitle(16sp) 与 screenTitle(22sp)。 真机字高 30px vs 探索页原生 38px —— 用户一眼就看出来了。
③ 空位 → 按用户拍板选 A
画廊头图 208dp → 148dp（设置子页那一档，不造新数字）。占位 状态栏 + 160dp → 状态栏 + 100dp。占位高与搜索卡落点必须同一个常量。

2根因①：钉高度用的 Modifier.height 把 miui 本体居中上顶了 18dp

本仓笔记里早有一条 "SizeNode 居中坑"，但只记了一半（子内容变矮 → 内容下移 δ/2）。 这条坑是双向的：

// Modifier.height(X) 报告的是 X；当子内容报出来的高度 ≠ X 时，
// 它交给父级的是"居中"，不是"顶部对齐"：
子内容更矮  ⇒ 内容被往下顶  (X − child) / 2
子内容更高  ⇒ 内容被往上顶  (child − X) / 2      ← 这次踩的是这一半

代入 miuix 本体的自然高度（`TopAppBar.kt:862-889`：`barHeight = collapsedHeight + expansion`， `contentTop = barHeight + LargeTitleBottomPadding`，外面还套一层 windowInsetsPadding(systemBars.Top)）：

自然高 = statusBarTop 37dp
       + CollapsedHeight 52dp
       + 空大标题那一行 ≈ 32dp   // largeTitle 传空串，但 `Text("")` 仍占一整行字体度量
       + LargeTitleBottomPadding 4dp
       ≈ 125dp

我钉的高度 = statusBarTop 37dp + CollapsedHeight 52dp = 89dp

被顶上去的量 = (125 − 89) / 2 ≈ 18dp      // 实测 44px ÷ 2.42 = 18.2dp ✔

三条独立证据

  • 同一颗盒子里两层错位：自绘标题 151.5（= miuix 正位）、本体 106 —— 差 44px。
  • 上一版截图里它还在正位：15:31 那张（还没有这个盒子）按钮中心 190px ÷ 3.0 = 63dp = statusBarTop + CollapsedHeight/2，正是 miuix 的正位。 两张图的状态栏、两枚圆钮的 x 逐像素重合 ⇒ 坐标同一套，insets 环境没有变 ⇒ 错位只能是这个盒子自己引入的。
  • 算式吻合：18dp 这个数不是凑出来的 —— 它由"空大标题那一行的高度"与两个已知常量算得。
教训（已写进长期记忆）："要裁掉多余部分"的地方一律自己 layout{} + place(0, 0)， 不许 Modifier.height —— 它的语义是"强制尺寸 + 居中"，不是"强制尺寸 + 顶部对齐"。

改法：两处都去读同一个主题槽位。这**不是**造一个没有出处的数字 —— 我们自己的 ui/tokens/MiuixTextStyles.kt 本来就把这两格映射到表里现成的档：

title1 = TextStyle(fontSize = t.display)      // 大标题那档
title3 = TextStyle(fontSize = t.statNumber)   // 折叠小标题那档（20sp）

于是：① 与原生同号；② 换风格档两处一起走；③ 页面里再也不出现"这一页的标题算哪一格"这种判断。

一处刻意的偏差：头图白字的字重仍留 weightSemibold，不跟原生大标题的 Normal。 理由是它压在亮度不可控的图上，白字要有一点厚度才压得住 —— 与顶 scrim 是同一件事的两个手段。 要完全照搬原生（Normal），说一声就改，一行的事。
⚠️ 上面那一条当天就被改判了（同日第二批，手册行 204）。用户真机口径是 「画廊的未收起大字和其他页面的字体和颜色对不上」「要全对齐，不然切换页面会很奇怪」—— "厚度压得住图"这一条让位给了切页一致性，字重已改成与原生逐字同值的 FontWeight.Normal，对比度从此只由顶 scrim 单独兜。 同一批还把左边距（rowHorizontal 14dp → TopAppBarDefaults.TitlePadding 26dp） 与顶边（space11 * 2 64dp → CollapsedHeight 52dp）一并钉到顶栏那一份常量上， 并把顶部 inset 的来源从 statusBars 换成 miuix 顶栏吃的 systemBars.only(Top)。 唯一保留的偏差是颜色（图上仍纯白）—— 那一格是报告里单独问过、用户当场拍的板。

4改法（三处）

① 钉高度那一路：自己 layout + place(0,0)

val pinnedBarHeightPx = with(density) {
    (statusBarTop + TopAppBarDefaults.CollapsedHeight).roundToPx()
}

if (pinCollapsedHeight) {
    Box(
        modifier = Modifier
            .fillMaxWidth()
            // ⚠️ 不许用 .height(...)：SizeNode 会把报高不一致的子内容居中上顶 18dp
            .layout { measurable, constraints ->
                val placeable = measurable.measure(
                    constraints.copy(minHeight = 0, maxHeight = pinnedBarHeightPx)
                )
                val width = if (constraints.maxWidth == Constraints.Infinity) {
                    placeable.width
                } else {
                    constraints.maxWidth
                }
                layout(width, pinnedBarHeightPx) { placeable.place(0, 0) }
            }
            .clipToBounds(),   // 裁掉那一整行空大标题（miuix 不看 maxHeight）
    ) { VeneraTopAppBarBody(...) }
}

② 两处字号改成读主题槽位

// VeneraTopAppBar.kt · 自绘小标题
fontSize = MiuixTheme.textStyles.title3.fontSize,
fontWeight = tokens.type.weightMedium,

// SettingsHero.kt · 头图上的白字（设置页与画廊首页共用这一颗件）
fontSize = MiuixTheme.textStyles.title1.fontSize,
fontWeight = tokens.type.weightSemibold,

③ 头图换档 A：两处必须同一个常量

// 两个消费点：SettingsHeroImage 的 totalHeight 与搜索卡落点 searchOverlayTop
totalHeight   = statusBarTop + VeneraSpacing.settingsHeroHeightSubpage,   // 148dp
searchOverlayTop = statusBarTop + VeneraSpacing.settingsHeroHeightSubpage
                 - VeneraSpacing.settingsHeroOverlap

5A 档的账（口径统一：淡出带 96dp 从画面底部往上算）

头图画面占位（墙里让出的高度）清晰区
旧 settingsHeroHeight 状态栏 + 208dp 状态栏 + 160dp 状态栏 + 112dp （24dp 机型 = 136dp）
新 …Subpage（A） 状态栏 + 148dp 状态栏 + 100dp 状态栏 + 52dp （24dp 机型 = 76dp）

注意"清晰区"与"占位"是两笔账：占位少了 60dp（用户要的"空位"就是这一段），但清晰区也同步矮了 60dp —— 这正是 A 与 B 的分水岭：B（加大 overlap）只减占位、不动清晰区，代价是搜索条压到清晰段上。

顺带如实纠一处我上一轮的说法："A 之后清晰区 76dp"这个数本身没错（那是按 24dp 状态栏的口径）， 但当时没写清口径，容易被读成"占位 − 淡出带"。正确写法是 清晰区 = 头图高 − 96dp（淡出带），其中头图高含状态栏。 本轮量到真机 statusBarTop ≈ 36dp ⇒ 新档清晰区 ≈ 88dp。标题（28sp）从 状态栏 + 64dp 起、 行盒到 ~96dp，即整行落在淡出带里（该处图约剩 54%–87%），靠顶 scrim 保对比； 与搜索入口条（状态栏 + 100dp）仍差 4dp，不重叠。
