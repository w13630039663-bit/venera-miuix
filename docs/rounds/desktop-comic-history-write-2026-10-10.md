# 批 82 · 阅读历史那一笔与那一屏（2026-10-10）

排期出处：`plans/clever-mesa-quail.md` 第 92 行 —— 「历史写口落地（`comic_history` 表已在桌面编译面、只有测试用过），

## 1. 这一批真正的风险在哪

`comic_history` 是**两端共用的一张表**（`data/db` 整目录在桌面编译面上，主键 `(comic_id, source_name)`）。
同一行数据两端各写一种形状，表现是"手机上的进度在桌面丢了"或反过来，而这张表没有版本号也没有迁移 ——
**漂了不会红**。所以这一批的字段的语义一律不"设计"，只回核对岸 `VeneraReaderScreen.kt:440-456` 那一处
`saveHistory(` 的每一个实参，并由判据回读那一段钉住。

## 2. 三条定案（本批自己定的，理由在此）

| 定案 | 理由 |
|---|---|
| 写口挂在**装载那一层**（`DesktopComicReaderPane`），而顶部页号从**提上来的 `LazyListState`** 取 | 展示件自己 `rememberLazyListState()` 时页号出不了那一件，写口只能恒写 `页=0` —— 而"翻页不记账"在屏上完全看不出来（批 82 接线判据 ①②） |
| 时机跟对岸：**顶部那一页一变就写一笔**，不是"退出时才写" | 对岸是 `LaunchedEffect(currentChapterIndex, currentPageIndex)`。跟它有两好处：跨端形状一致；退出时那一笔天然被 `NonCancellable` 包住。计划里那句"退出阅读时写一笔"落地成它的**超集** |
| 章号（`lastChapterIndex`）从详情那一屏的**行号**一路带到库里 | 手机侧读它续读。桌面从前没有这一档（载荷里只有话号），填错一档 = 把另一端的进度挪到别的话。`--read=` 那颗种子不知道行号，只能给 0，而它只跑在隔离数据目录里 |

## 3. 一屏一源那一档（读侧最要紧的一条边界）

漫画域一趟只装载 `config.sourceKey` 那一个源，运行期不换。库里的行记着它是哪一站的，于是：
**异源那一行摆出来、念出自己是谁的源、但不做成能点的样子**，并上屏一句「换源启动才打得开」。
拿错的源去问同一个号只会问出别的东西 —— 与"拿 A 站凭据发给 B 站"那一族同源。
判据两层各钉一次：源码扫描钉 `Modifier.clickable` 恰一处且那一行含 `canOpen`，语义树钉那一行按下去零笔。

## 4. 看得见与看不见的失败（这一格没验，别当成覆盖）

`DesktopComicHistoryPane` 的 `note` 只有一个来源：`config.history()` 那颗件**建不起来**（端口没装、库文件开不了）。
而"建起来了、那条 `SELECT` 抛了"落在 `HistoryDao.refresh` 自己那根 `scope.launch(Dispatchers.IO)` 里
（`HistoryDao.kt:48-53`，`getAllHistorySync` 是 private，桌面侧够不着返回值），
屏上拿不到那一笔 —— 那种失败今天只在 stdout 上响，而屏上会画成空态。
**这一格本批没验，也不许在屏上或手册里写成"读侧故障也有读数"。**

## 7. 两格没验（写清楚，不当覆盖）

1. **「那条 SELECT 抛了」屏上看不见。** `HistoryDao.getAllHistorySync` 是 private，而 `refresh()` 自己 `scope.launch(Dispatchers.IO)`
   —— 异常落在那根协程里，只会在 stdout 上响。所以 `DesktopComicHistoryPane` 的 `note` 只覆盖"那颗件建不起来"一种失败；
   库里**有**行而读失败时，屏上画的是空态。这一格要么改对岸那颗件（受保域，等点头），要么给桌面另开一条能拿到异常的读路，
   本批都不做，只做了一句实话：`DesktopComicHistoryScreen.kt` 的类注释里写明"这一格没验"。
2. **「滚到哪一页就记到哪一页」离屏量不出。** 第一版判据真 `scrollToItem(3)`，`firstVisibleItemIndex` 仍是 0；
   换 `rememberLazyListState(initialFirstVisibleItemIndex = 3)` 也是 0，而 `layoutInfo.visibleItemsInfo` 有货
   ⇒ 离屏那一屏的列表状态不反映滚动，拿它量"跟不跟手"会**恒绿**（一把不动的尺子）。真滚一次要 OS 级输入，那一条被明令禁掉。
   于是这一层只留两档量得到的（页表没到手一笔都不发、到手那一笔字段逐项落对），
   "页号从 `listState` 取而不是写死 0"退到由 `DesktopComicHistoryWiringTest` ① 钉形状 + 真跑那一页的读数（`页=0/89` 起手那一笔）。
   ⚠️ 这条与批 81 §11.3 那条滚动缺口是**同一格**，不是新格 —— 两批都没量到。

> **2026-10-10 当日改判（批 82.5）**：这一格后来**有正面读数了**，但不是靠离屏那把尺子 ——
> 给阅读那一屏补了一枚 `--read-page=<索引>` 种子，真窗口里念出
> `请求=7 量到=7 页表=89 试=8` → `D_历史 写 … 页=7/89` → 库里 `last_page_index=7`，
> 也就是说"顶部那一页一变就写一笔"在真窗口里跟着动，那颗写口**不是假开关**。
> 顺带量掉两笔：`scrollToItem` 在列表"量过一次"之后仍不落（两种等法都被念成 `没落到`），只有重试到落定才落。
> 读数、五趟对照与还欠的三格见 `desktop-reader-start-page-2026-10-10.md`。
> 上面那句"离屏那把尺子不动"**不改**：同一枚 `scrollToItem` 在真窗口能落定而在 `runComposeUiTest` 里量不到。
