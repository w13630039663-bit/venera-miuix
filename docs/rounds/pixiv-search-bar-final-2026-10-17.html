pixiv 搜索栏 · A + D 定稿

触发：首页那一排内容域从「图库站」切到「Pixiv」。范围：展开的搜索卡 + 收起态的摘要行。依据：GallerySearchSource.kt / GalleryHomeDomain.kt / GallerySearchViewModel.kt / PixivClient.kt 实读。

形态：A 的骨架 + D 的标签模式 —— 排序一行、筛选一枚钮（抽屉里四段：收藏 / 作品 / 画面比例 / 发布时间），「标签部分 / 标签完全」搬进输入框左端当 token。

切域：整张卡跟着换。Pixiv 档没有来源轴那排分段器（pixiv 本来就不在那条轴上），那 44dp 换成了排序行 + 筛选钮。词与标签跟着人走，pixiv 自己的排序与筛选按域记。

历史：存储不动 —— 一条词 + 它搜过的站，读的时候按域过滤。图库站看不到 pixiv 的历史，反之亦然。

一、先把「内容域」和「来源轴」分开

这是上一稿画错的地方：我把 pixiv 画进了卡里那排分段器。它不在那条轴上，而且是有意剥出去的。

内容域 · 首页那一排
决定「这一屏吃什么料」：图库站三节，还是 pixiv 三节。
图库站 Pixiv
来源轴 · 搜索卡里那排
决定「这一句搜哪几站」。pixiv 不在这里，只有这三站 + 全部。
全部 yande.re Gelbooru Safebooru Pixiv

为什么 pixiv 不在来源轴上（源码里的原话，不是我的推断）

booru 三站吃的是 tags=a+b order:score 那一套；pixiv 吃的是「一个词 + 站内 s_mode / order / blt / scd…」。并进「全部」就是半面墙按标签、半面墙按另一套语法 —— 那是假读数，不是数据墙。

所以定稿走的是：域切到 Pixiv ⇒ 卡里那排分段器整块不摆，换成排序 + 筛选。换回图库站，那排分段器原样回来（还停在原来那一档）。

⚠️ 这一版要接的是一条新搜索腿，不是只改卡

GallerySearchViewModel.searchLeg 里，GallerySite.PIXIV 现在是 notWired("搜索腿") —— 直接抛「pixiv 走到搜索这一路，但它的取数还没接线」。也就是说：卡画得再对，pixiv 搜索现在跑不起来。

真正的工作量在：接上 PixivClient.tagWorks 那条腿 + 把六个筛选参数串进去 + 把「一个词」与「多枚标签胶囊」对齐（booru 是多标签 AND，pixiv 那一跳是单关键词）。这一条不先做，后面全是空转。

二、两副样子

同一张卡、同一个位置，切域之后换的是里面那一块 —— 输入行一动不动。

两张卡的高度差：图库站 约 257dp，Pixiv 约 245dp —— 差的这 12dp 就是「来源轴 44」换成「排序行 32」的净变化。输入行在两张卡里的位置完全一致（卡顶 16 + 56），所以切域那一下输入行不动，长出来的只有它下面那一块。

有生效条件时：多一行

排序行下面会长出 32dp 的条件行，每枚带 ×。这一行只有 pixiv 档有（图库站的条件是标签胶囊，住在输入行上面那条，今天的样子）。

Pixiv 档 · 条件行 32dp 收藏 500+ 横图 标签完全

标签模式改了档也会出现在这里 —— 它虽然住在框里，但它是「生效中的条件」，不能在条件行里缺席。点这一枚 × ＝ 退回「部分」，框里那枚 token 同时回档。

三、筛选抽屉

四段。标签模式不在里面（它搬进框了），所以抽屉比上一稿短一截，翻找更快。

为什么标签模式在框里（D 的那一刀）

「部分 / 完全」决定的是你敲进去那串字怎么匹配，不是「筛掉哪些结果」—— 它属于输入，不属于筛选。放进框里之后：敲词的时候它就在光标旁边，改它不用开抽屉，抽屉也因此从五段降到四段。

代价照实说：输入区少约 64dp，前导那枚放大镜让位给 token。所以框里的 token 用「部分」两个字，不用「标签部分」四个字 —— 省一半宽度，位置又贴着输入区，读起来不会歧义。

四、切域：变什么、不变什么

件图库站档Pixiv 档切的那一下

结果墙——切域即清，回输入态

动效只有一条规矩：新块一律长在输入行下面

输入行是这张卡的锚点（也是共享元素那一端）。把它按住不动、只让下面那块长高，切域读起来才是「同一块面换了内脏」，而不是「换了一张卡」。反过来把排序行摆在输入行上面，切域那一下整行会往下跳 32dp —— 那一下最像卡顿。

时长与曲线取卡里既有那对：expandVertically + fadeIn，motion.medium。不新立数字。

五、历史分离

不用改存储。历史条目本来就长这样：一条词 + 它搜过的站集合（GallerySearchEntry.sites，落盘的编码里已经带着）。所以「分离」是读的时候按域过滤，不是复制成两本账。

存下来的词记下的站图库站档看得见Pixiv 档看得见
loliyande.re看得见—
全职猎人yande.re · Gelbooru看得见—
オリジナルPixiv—看得见
横長Pixiv · yande.re看得见看得见

最后那条是关键：同一个词在两处都搜过，它只会是一条，两档都看得见 —— 因为它确实在两处搜过。这跟「复制成两本账」的差别是：复制之后，「横長」会变成两条、删一条另一条还在，用户没法理解哪条才算。

三条细则

  1. 清空只清当前域。不是整条删 —— 把当前域从每条历史的站集合里摘掉，摘空了才删。所以 pixiv 档点「清空」，「横長」会留下、只是不再出现在 pixiv 档（它还挂在 yande.re 上）。
  2. 点历史不换域。现在 applyHistory 会按 entry.sites 换来源；分离之后这条要改成用当前域去搜。否则在 pixiv 档点一条「Pixiv · yande.re」的旧词，会莫名其妙跳回图库站。
  3. 历史那一行的小徽标不变。Y / G / P 是「这条搜过哪些站」，它现在正好兼任「为什么这条会出现在这一档」的解释。

六、状态归属

状态归属为什么
输入中的词跨域共享「换个域搜同一个词」正是切域最常见的动机，切一下就清空等于让人重打一遍
标签胶囊跨域共享它们是「搜什么」，两站都认这个词
排序 / 标签模式 / 收藏 / 作品 / 比例 / 时间pixiv 专属，切走保留只对 pixiv 有意义；切回来原样还在（内存里，不落盘）
图库站那排来源轴选中哪一档保留切去 pixiv 再切回来，还停在 yande.re 那一档
历史一份存储，按域过滤见第五节
结果 / 分页 / 失败腿切域即清那一轮结果属于另一个域，留着就是「pixiv 屏上摆着 booru 的图」

为什么不做成「每个域一份完整草稿」

那样切到 pixiv 时，框里是空的 —— 刚在图库站搜的那个词要重打一遍。而「把这个词换个域再搜一次」恰恰是这个切换器最常用的用法。所以：搜什么共享，这一域怎么筛各自记。

唯一要盯的是「标签胶囊共享」这条：pixiv 那一跳是单关键词、booru 是多标签 AND。多枚胶囊切到 pixiv 时怎么落地（只取第一枚？拼成一个词？）是接腿那一步必须定的 —— 见第七节第 2 条。

七、落地清单

#落点做什么
1gallery/ui/GallerySearchViewModel.searchLeg把 PIXIV -> notWired("搜索腿") 换成真腿：PixivClient.tagWorks(词, 页)。这是整件事的地基。
2同上，词与胶囊的对齐booru 是多标签 AND，pixiv 是单关键词。建议第一版只取第一枚包含型标签，多枚时在卡上说一句「pixiv 只按第一个标签搜」—— 静默丢掉另外几枚是最坏的长相。
3gallery/domain/PixivSearchFilter.kt（新）三个枚举（排序 / 作品 / 比例）+ 收藏档位 + 标签模式；isDefault() 与 toQuerySuffix() 都是纯函数，好上单测。默认档一个参数都不发。
4GallerySearchViewModel七个 pixiv 状态（默认中性）；switchDomain：清结果、回输入态、pixiv 状态保留；visibleHistory 按域过滤；clearHistory 摘站不整条删；applyHistory 不再换源。
5gallery/ui/GallerySearchArea.kt按域分两副：来源轴 if (domain == BOORU)；pixiv 档加 token / 排序行 / 筛选钮 / 条件行，全部包在 AnimatedVisibility 里（160ms）。
6gallery/ui/GallerySearchPixivSheet.kt（新）四段抽屉 + 收藏刻度尺 + 日期区间。复用 GallerySheetBlock 那套壳，不另造抽屉。
7单测PixivSearchFilterTest（默认档不发参数、日期序列化、收藏档位映射）＋ GallerySearchHistoryPerDomainTest（过滤 / 清空只摘当前域 / 应用历史不换源）。

历史那条 history 键名不变，不需要数据迁移 —— 编码里已经带着站集合。这是这个方案最省的一处，也是唯一一处不用动的地方。

八、两条待定

  1. 默认排序取哪一档？ 稿上按「人气」画的。站方默认是「最新」—— 跟站方走的话第一次进来一个参数都不用发，与「默认档不发参数」那条纪律天然对齐。要定「人气」也行，只是每次开搜都多一个参数。
  2. pixiv 档的占位文案要不要带站名？ 我按「不带」画的（与图库站同一句）。理由是这一屏的域在上一行刚点过；但卡一展开就把那一行盖住了，所以也可能该写成「在 Pixiv 搜标签 / 画师」。这一条我按不带画，你定。
