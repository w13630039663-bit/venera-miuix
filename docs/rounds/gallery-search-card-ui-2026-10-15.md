# 画廊搜索卡 UI 优化方案（2026-10-15）

题面 = 用户给真机截图（展开态搜索卡）并说「这是目前的搜索框，而且还是没有容器变化动画，以及你看下这个 ui 可以怎么优化」。
本文件只谈**观感与结构**；容器动画那一格的真根因写在最后一节（另批修）。

参考图：`Screenshot_2026-10-15-10-58-37-58`（1080×2376，浅色主题，禁漫之外的画廊两站 + Safebooru 三档）。
所有像素值由 `_qa/shot_measure.ps1` / `_qa/shot_profile.ps1` 现量（System.Drawing 逐像素，不是目测）。
dp 折算按 **2.875 px/dp**（由卡片左右内缩 46px = `screenHorizontal` 16dp 反推；本机未连，拿不到 `wm density` 直读）。

## 一、现量设计系统（这张卡）

| 项 | 现量 | 对应令牌 / 代码 |
|---|---|---|
| 卡底 | `#F4E4E5` | `color.surfaceContainerHigh`（浅色主题被动态取色染粉） |
| 选中药丸底 / 字 | `#A63257` / `#FFF4FD` | `VeneraSegmentedButton` 选中档 = `primary` |
| 未选药丸底 | `#FFDDE5` | 同一件的未选档 |
| 正文 | `#23191A`，字带高 34px ≈ 12dp | `type.body` + `textPrimary` |
| 节头 | 字带高 27px， tertiary 灰 | `type.caption` + `textTertiary` |
| 卡片 | y 404..1281 ⇒ 高 **877px ≈ 305dp**，占屏高 **37%** | 浮层，锚 `topBarFloor` |
| 分段器带 | y 469..594 ⇒ **126px ≈ 44dp** | `segmentedHeight` 48dp 那一档 |
| 推荐行 pitch | 707→833 ⇒ **126px ≈ 44dp** | `listRowMinHeight` 48dp（`GallerySearchArea.kt:1386`） |
| 历史行 pitch | 1018→1102→1189 ⇒ **84 / 87px ≈ 29–30dp** | `VeneraChip` 自持高 + `space2` 行距（`:1504`） |
| 块间距 | 输入→分段 16px；分段→节头 26px；节头→其内容 57–61px；末行→卡底 63px | `space1/3/4/6` 混用 |
| 卡底外那条暗线 | y 1277..1285 | `elevation` 投影边 |

对比度实算（WCAG 相对亮度）：

- 未选药丸 `#FFDDE5` vs 卡底 `#F4E4E5` = **1.02 : 1** ⇒ 药丸轮廓**看不见**；
- 未选药丸上的字 `#23191A` vs `#FFDDE5` = 13.7 : 1 ⇒ 字没问题；
- 选中药丸 `#A63257` vs 卡底 = 5.30 : 1，白字 vs 药丸 = 6.5 : 1 ⇒ 选中态很稳。

结论：这一排不是"读不清"，是**"看不出这是一档一档可切的"** —— 而未选态那几颗是**当前唯一的换源入口**（上一批刚把首页那一排摘掉）。

## 二、优化项（按"值不值得动"排）

### U1 未选药丸在实色卡底上消失（最要紧，且是上一批自己放大的）

- 病：1.02:1 的容器差；四颗里只有「全部」看得出被选中，其余三颗与卡底同色 ⇒ 换源入口不像入口。
- 改法（两档，都要点头，因为动的是共享件 `components/venera/VeneraSegmentedButton.kt`）：
  - **a 档**：未选档底色从当前那层换深一档（`surfaceContainerHighest` 那一族），选中照旧 `primary`。三处调用点（`FavoritesScreen.kt:628,654` + 卡内 `:681`）一起变。
  - **b 档**：只在**不透明底**上补 0.5dp 描边（`outline`，不是 `outlineVariant`）。前科要认：2026-09-28 那次把描边换成自持药丸，是因为 0.5dp `outlineVariant` 贴在**实时模糊的玻璃**上几乎看不见 —— 而这张卡是实色 `surfaceContainerHigh`，描边在这里成立。所以 b 档不推翻那次拍板，只是给它加一个前提分支。
- 本鱼推荐 **a 档**：不引入"同一件在两种底上长两种样"的分支，判据也简单（未选底与卡底的对比度 ≥ 1.15:1，可以现量钉死）。

### U2 同一张卡里两种"可选行"节奏

- 病：推荐行 pitch 44dp、历史行 pitch 30dp，两区讲的是同一类东西（一行 = 一条可点的搜索条件 + 站点信息），却两种高度、两种件（裸 Row vs `VeneraChip`）。
- 改法：推荐行改成与历史同一枚 `VeneraChip`（`Neutral` 档 + `leadingText` 徽标 + 尾部不放 ×），两区就只剩"节头 + 一排 chips"一种语言；卡片因此省约 **44dp**（两行 88dp → 一排 chips ~30dp + 行距）。
- 风险：推荐串通常比历史串长，chip 化后省略更狠 —— 但这一块的用途本来就是"认出这条我要"，不是读全文（历史区 2026-09-30 真机反馈已经验证过这个判断）。

### U3 卡片吃掉 37% 屏，只装 5 条可选

- 病：877px 高、可见内容 2 条推荐 + 3 条历史（第 4 条要滚）。
- 改法：U2 落地之后再收一档 —— 推荐区**最多 2 条**（现在就是每站一条，天然 ≤2）；历史区限高从 `listMaxHeight`（`listRowMinHeight × N`，`:187`）改按 chip 档算，别按 48dp 行算。
- 目标数：卡片从 ~305dp 收到 **~240dp**（≈ 屏高 29%），键盘起来后墙上还能看见一整行图。

### U4 历史被卡底裁掉却没有任何暗示

- 病：末行字带到 1218、卡底 1281，中间 63px 是内缩，不露"下面还有"。用户不知道这块能滚（`HistoryList` 外层是 `verticalScroll`，`:1478`）。
- 改法：给那一格加一枚**底部渐隐**（现成件里有 `Modifier` 层的 fade，或用一条 8dp 高的垂直渐变），并在节头那行念一句「共 N 条」（现数：`svm.history.size`）。
- 口径依据：本仓对"能滚但看不出来"这类事的一致态度是**给读数**，不是静默（同「少了一站必须占一条可见的位置」那条）。

### U5 三站时 `Y·G·S` 这类缩写读不出信息

- 病：`gallerySourceMarkText(entry.sites)` 在单站时是好东西（一枚字母），三站时变成 `Y·G·S` 一串自造缩写。
- 改法：**多站合并成一枚「N 站」**（数字自解释），单站照旧字母徽标。
- 不要提的：把站名整行摆出来 —— 2026-09-30 真机反馈已否过（会把关键词挤没，见 `:1488-1490` 注）。

### U6 卡内纵向节奏混档

- 病：块内 16–26px、块间 57–68px，但代码里是 `space1/space3/space4/space6` 四种混着写（`:691,710,722,746,779`），没有"块内一档 / 块间一档"的规矩。
- 改法：定两条并写进判据 —— 节头→其内容恒 `space1`，块与块恒 `space4`；分段器→下一块恒 `space3`。
- 收益小但便宜：它让 U2/U3 收完之后不必再逐处看。

### 不算缺陷、但值得记一笔的两条

- 关闭出口在**顶栏**那枚随状态换形的图标（`GalleryScreen.kt:1065`：`if (svm.active) Close else Search`），卡上没有 ✕。这是刻意的（同一枚图标两态互斥），只是"卡上没把手"这件事值得知道是选过的，不是漏的。
- 四档时分段器最后一颗截成「Safebo…」。MD3 对 2–5 项的标准件就是分段器不横滑（`:677-680` 已写明），所以这一格要么缩标签、要么等 Safebooru 那档被用户自己关掉 —— 本批不动。

## 三、建议打包

- **第一包（便宜、收益最大）**：U1(a) + U2 + U4。三条都在"这一张卡"内，U1 需点头（动共享件、三处调用点同变）。
- **第二包**：U3 + U5 + U6（收密度与节奏，读完第一包的观感再定）。

## 四、容器动画那一格（另批修，根因已定位）

`GalleryScreen.kt:1137` 是 `if (svm.active) { … AnimatedVisibility(visible = !searchCollapsed) … }` ——
`AnimatedVisibility` **被包在 `if` 里**：开搜索那一刻它是**新组合进来的**，初值就等于目标值 `true`，没有"从 false 变到 true"这一跳 ⇒ `enter` 那套 `fadeIn + scaleIn` 根本不播（它只在 `searchCollapsed` 随滚动翻档时播）。
所以"没有过渡"不是缺动画定义，而是**动画挂在一次不会被观察到的状态变化上**。修法是把 `AnimatedVisibility` 提到 `if` 外面、让 `visible` 自己吃 `svm.active`（scrim 同理）。

## 五、同日落地（2026-10-15 批 189）

用户口径是「根据他这种的ui优化下，你看情况点，其他的按照你说」——参考图那张给的是**行状推荐**，所以"看情况"这一格改了本方案的两条：

| 编号 | 方案里的判断 | 实际怎么做的 | 为什么 |
|---|---|---|---|
| U1 | 分段器未选中格在卡底上无边界（现量 **1.02:1**） | **做**：`VeneraSegmentedButton` 加 `SegmentedBackdrop`，`Opaque` 档给未选中格加 `hairline` 描边 | 动共享件，三处调用点同变：`FavoritesScreen` 两处显式取 `Glass`（逐字不变），卡内取 `Opaque` |
| U2 | 推荐行改成一格一格的缩略卡 | **撤销**，改成"描边容器 + 行间 `HorizontalDivider` + 行尾 `KeyboardArrowRight`" | 参考图自己给的就是行状；拆成缩略卡会把已验证的取用密度降档。**这条是本方案被参考图否掉的一格** |
| U3 | 输入行与尾随动作糊成一坨 | **做**：输入行改成描边胶囊（`percent = 50` + `space1/2`），中间加一条 `fillMaxHeight` 竖向分隔 | 让"哪些是框、哪些是动作"看得见 |
| U4 | 历史筹码 `Neutral` 与卡底同色 | **做**：换 `Assist` | 与 U1 同一类病（填充与背景同颗） |
| U5 | 三站合并写成 `Y·G·S` 自造缩写 | **不搬**"N 站"那版 | 参考图保留缩写；且换整名会挤爆分段器最后一颗 |
| U6 | 纵向节奏四档混用 | **基本没动** | 参考图这一格没给新证据；U2/U3 收完之后密度问题已经不明显，剩下的属于"重排而不改观感" |
| 标题 | 「最近搜索」不带数 | **做**：改成「最近搜索 · 共 N 条」 | 从前分不清"清掉了"还是"本来没搜过" |

**动画那一格照 §四 的根因修了**，并写成负向判式（`GalleryHomeChromeTest` 第⑤条）：`visible = svm.active && …` 必须在，且 `if (svm.active) {` 之后三行内不许再出现 `AnimatedVisibility(` —— 否则这条改动会静默退回"看不见的动画"。

⚠️ 本文上面各条里引的 `:691`、`:1137` 那类行号是**改版前**的读数，落地后已漂；要按符号名回代码定位，别拿行号当真。

## 七、正解落地：色调台阶（同日，用户「除了这些整个ui直接改成图一吧」）

撤完描边不等于回到原点 —— 参考图那套层次的账是逐像素量出来的：

| 哪一档 | 参考图 | 我们（改版前） | 台阶 |
|---|---|---|---|
| 卡底 | #FCF0F0 | #EAE7EE | 基准 |
| 输入行 | #F6EAEA 填充 | 无底 | 1.000:1 |
| 未选药丸 | #F0E4E4 填充 | surfaceVariant 叠 0.5 alpha | 1.021:1 |
| 推荐两行 | 一整块填充容器 | 无底 | 1.000:1 |
| 历史筹码 | #F0E4E4 填充 | Neutral 档 = 与卡底同一颗 token | 1.000:1 |

**全卡零描边** —— 参考图从头到尾没有一根线，它的层次全靠低一档的底。所以这一批做的事只有一句：**该有底的四格补上 **surfaceVariant**，线一根都不画**。

- 分段器重开 `SegmentedBackdrop` 那枚必填参数，但 `Opaque` 档这次给的是**不透明底色**而不是描边；`Glass` 档逐字维持（收藏页那两排仍半透明 —— 玻璃上涂实底会拉硬边，那条拍板不动）。
- `VeneraChip` 新增 `Tonal`：填 `surfaceVariant`、无描边、显式不吃玻璃。`Neutral` 那档的问题不是选错色，而是它填的 `surfaceContainerHigh` **就是卡底那颗** —— 住在卡里必然 1.000:1。
- 输入行那颗仍是**定高**（§189b 那枚整屏拱门的教训按真形状补进了判式）。
- **遮罩刻意不抬**：参考图顶部背景 #9E9294 vs 我们 #9593A0，量下来没差别 —— 那句「参考图的卡更浮」是台阶差，不是遮罩差。
- 卡内缩也不动：参考图约 12dp，我们是现成的 16dp 档，不为一格立新数字。

判据 4 条在 `GallerySearchCardTonalTest`（其中「整颗文件不许出现 `BorderStroke(` / `.border(`」是**负向尺**，防的就是下一批又拿线解决问题）。台账与数字见手册 §190。
