v3 · 沉浸画布 + 底部毛玻璃抽屉

按你说的做了一版：首屏画布吃满 90% 视口（图出血到状态栏之上），画师头像 / 标题 / 多图进度收进一条毛玻璃抽屉卡， 叠在画布底部只露一行；手指上滑 → 抽屉平滑推起，标签、数据、评论、相关图片依次展开，操作栏住在抽屉里跟着一起走。 下面八张屏是这条链的四个锚点态 + 两个特殊态 + 宽屏档 + 状态机；假数据只为看密度与层次。

抽屉三档锚点（812dp 高的机）

  • peek 88dp（10.8%）= 把手 12 + 一行 64 + 距底 12
  • half 365dp（45%）= 画师 + 标签 + 数据条
  • full 747dp（92%）= 顶部留 65dp 给状态栏与 sticky 页码
  • 档位间距用现成档：space36 / sheetActionHeight48 / topBarCollapsedHeight52

手势归属（这一版最容易出事的地方）

  • 画布横滑 = pager 切页（peek 与 half 都归它）
  • 画布竖滑 = 推起抽屉（不是切页、不是滚详情）
  • 抽屉内竖滑 = full 态滚内容；到顶再下拉 = 交还给抽屉降档
  • 双指 = 缩放层；缩放 >1x 时拖动归缩放层，1x 把竖滑交还抽屉
  • peek 态再下拉 = 关闭这一屏（与系统返回同一档）

先说风险：这颗坑本仓踩过

  • 抽屉要落 miuix 的 AnchoredDraggable / BottomSheet —— 手册行 202 记过：库里那个 dragTarget 赋值点没有 finally 兜底，一旦卡住，内容层吃掉每一笔 DOWN，整屏点不动而拖动照常。
  • 现成的解就在 GalleryInfoSheet（落定看门狗 + fingerDown 那道门）。抽屉这一屏必须复用同一套，不能另写一份拖拽。
  • 抽屉与画布是两个滚动者 ⇒ 本仓 LazyVerticalGrid × verticalScroll 那一族整屏崩的近亲，full 态只许一个滚动容器。

三 · 这一版还要再优化的细节

peek 那一行放什么要抠 现在是「头像 + 标题 + 页数/收藏/评论 + 关注」。页数与评论都要？本鱼建议留 3/8 · 1.2k，评论数挪到操作栏那枚角标上（已经有了，别念两遍）。同一件事只许一处说。
首次进入给一次"能上滑"的暗示 抽屉进来时自己弹一次 half 再回 peek（300ms，只给一次，存"看过"标记），比摆一个箭头文案诚实。别用红点。
推起过程里画布要跟着缩，不要盖住 抽屉高度 1:1 驱动画布底边（画布按比例缩、不裁），到 half 时图仍完整可读；绝不"抽屉浮在图上不动"，那会把图的主体压掉。
full 档换实底，半档保留玻璃 玻璃只服务 chrome（peek/half 那一行）；正文一进入长文本就换 surface。与首页"玻璃不挡采样、内容列不吃玻璃"同一条。
切页后抽屉档位不变 翻页时把 pager 的页码胶囊与缩略条选中态一起更新，不重置锚点（重置就是"页面在抽风"）。
下拉关闭与系统返回只留一条出口 peek 下拉、返回键、预测式返回三者走同一条 close，不许各写一份动画。
风险 · miuix 拖拽那颗卡死 AnchoredDraggable 的 dragTarget 没有 finally 兜底，卡住时内容点不动而拖动照常（手册行 202 的现量）。 这一屏必须复用 GalleryInfoSheet 那颗落定看门狗 + fingerDown 那道门，并给它配判据：抽屉在 full 档时内容层的点击必须落得下去。
风险 · 两个滚动者 full 档只许一个滚动容器（画布那条 sticky 不参与滚）。本仓 LazyVerticalGrid × verticalScroll 那族整屏崩的教训就写在这条旁边。
风险 · 评论数据面还没通 匿名侧四个形状全 404（现量 2026-10-18），只有 /ajax/illust/{id} 给 commentCount 与 commentOff。 ⇒ 抽屉里的评论摘要与整屏都要走登录腿；拿不到就把那一节整块撤下，不摆空壳。

假数据只为看密度；色阶与胶囊全部取自画廊现状（#EFDCD5 氛围层、#F6E4E2 卡底、#1F1F1F@.80 图上胶囊、玻璃圆座视觉 40 / 触达 48）； 图标全部线性 SVG；可点处 ≥48dp；动效走 VeneraMotionTokens。代码一行未动。
