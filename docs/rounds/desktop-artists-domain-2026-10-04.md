## 1. 这批做什么

rail 上剩两枚坦白页，这批接掉其中一枚：

- **`ARTISTS` 域转正**：目的地是「关注画师」整页 —— 本机名单摆全，每位一行（圆座 + 名字 + 站点与名下张数）。
  七枚导航域现在是 **6 枚真能进 + 1 枚坦白页**（只剩「发现」）。
- **撤掉一条已经不实的读数**：图库首页那一栏从 S2 起就写着
  「头像与名下收藏图本轮不显示：桌面还没有图库的取图件，卡面一律首字母座」——
  而**第四批起三面墙就在用 `coil3.compose.AsyncImage` 取图**。那句话现在是假的，整句撤掉，
  换成真在发生的那三档（见 §3）。

## 2. 这一屏与首页那一栏**同源**，差别只有一个：截不截断

名单、跨站同人、排位、名下张数、圆座三档五条判据全在共享那颗 `GalleryFollowedArtists` 里
（Android 首页那一栏读的也是同一颗）。桌面这边新加的是**一颗判据件 + 一颗行 composable + 一句读数说明**，
两处共用：

| 东西 | 首页那一栏 | 画师域整页 |
|---|---|---|
| 读数 | `desktopFollowedArtistsRowReadout` → `rowOf(follows, favorites)`（横卡 8 位，`overflow` 念出来） | `desktopArtistsReadout` → `rowOf(…, DESKTOP_ARTISTS_PAGE_SIZE)`（整页摆全，`overflow` 恒 0） |
| 行 | `DesktopFollowedArtistRow(artist, face)` | 同一颗 |
| 圆座 | `desktopArtistFace(faces[name], previewUrl)` → 转交 `faceOf` | 同一颗 |
| 三档说明 | `DesktopArtistFaceCaliberCaption` | 同一颗常量 |

**"截不截断"为什么要命名成两颗函数而不是一个 `rowSize` 形参**：两处都直接调 `rowOf` 时，
下一次有人把首页那栏改成整页，很容易把 `Int.MAX_VALUE` 一起抄过去 —— 首页那一栏就变成一条无限长的横排。
分开命名之后这件事在类型上看得见。

同理，`DesktopGallerySectionContent` 里新加的是**第二枚**内容件（`ArtistsWall`），
不复用首页那枚 `FollowedArtists` —— sealed 的 `when` 不留 `else`，加一档忘了出形状就编译不过。

## 3. 这一屏只读，而缺的**三层**各自点名

| 缺的那层 | 屏上那句 |
|---|---|
| 画师单人页（P5 没搬） | 「这一屏的卡位不可点：桌面没有画师单人页。要看某位的图，去「搜索」那一屏输入他的名字。」 |
| 头像现取 | 「这一屏不主动去站方取头像，所以只关注没收藏的那几位落字母座；图坏了也落字母座。」 |
| 关注动作的入口 | 「关注这个动作在桌面还没有入口：它挂在画廊的画师那一屏上，而那一屏没搬过来。这一屏只念本机已有的名单，不替你猜该关注谁。」 |

三条都不是"暂不支持"那种措辞。**「没取到 / 没有 / 没接」是三句话**（手册 §12），
这里第四种形状也一样：「没接、但接的那一侧行为不同」—— 画廊那侧是"面板打开才现取一次"，
桌面这侧只读本机档，这句不摆出来就会被读成"这位没有头像"。

段头那两个数也都是现算的真读数：`本机关注 3 条 · 跨站同名并成 2 位`。
只念后一个会把"两站都关注过同一个人"这件事抹平。

## 4. 判据 +9（`DesktopArtistsWallTest`）

| # | 钉什么 |
|---|---|
| ① | 这一域转正后只有一行、`content` 非空、`reason` 为空（真页面的形状），对照组拿设置域那一行 |
| ② | **整页摆全而横卡仍只摆八位**：12 位样本下 `rowOf` 默认截到 8 且 `overflow=4`，整页那颗 12 且 `overflow=0` |
| ③ | 跨站同名并成一条，且站点徽标次序恒为枚举自然序（不跟关注时刻飘） |
| ④ | 合并后那条的**排位**取组里最近一次关注 |
| ⑤ | 圆座三档：真头像 > 名下收藏图 > `null`；空串与空白都不算值 |
| ⑥ | 空名单是 `NO_FOLLOWS` 那一档，不是"零位热门" |
| ⑦ | 桌面不许另立一套同人与排序：`groupBy` / `sortedWith` / `lowercase()` / `distinctBy` / `sortBy` 在**三颗件**的代码行里都不许出现 |
| ⑧ | 首页那一栏那句已不实的读数不许再出现（`还没有图库的取图件` / `一律首字母座`），撤掉之后必须换成真转交 |
| ⑨ | 「不主动去站方取头像」这一档必须摆得上屏（断言的是那句常量的**值** + 整页确实引用它） |

⑦ 扫**三颗**而不是只扫 policy：判据一旦从 policy 挪进 UI 文件，只扫 policy 就等于没扫。
⑨ 断言常量值而不是扫整页文本 —— 那句说明住在共用常量里，扫文件会因为 `codeText` 跳注释而抓不到东西。

## 6. 三条过程读数

1. **一条假读数为什么能活四批**：那句「桌面还没有图库的取图件」同时存在于注释与**屏上字面**，
   而它住的那一栏在图库域里 —— 前四批的图证拍的都是日榜墙与搜索墙，**这一栏从没被拍过**。
   判据也抓不到它：它是一句真话的过去式。⇒ 新增/改动任何一屏时，**那一屏要单独拍一次**，
   不能拿同域另一屏的图证顶替。
2. **自己刚写的对照组要当缺陷审**：⑦ 最初那条对照组写的是
   `assertTrue("codeText 读空了", policy.contains("internal fun").not())` —— 断言写反了，
   而 policy 文件里**本来就有** `internal fun`，跑起来必红。它在实现之前就被自审抓到，
   改成正向断言 + 另加一条"整页确实在调圆座判据"。同族教训见手册 §4.1。
3. **窗口标题带 PID，判"这一帧是不是这扇窗"比比对 bounds 强**：手册 §16.4 记的是"起窗后抓两次、
   比对 bounds 与内容"；这一批发现标题本身就是 `Venera Desktop R1-F 最小闭环 #19956`，
   与 `list_windows` 拿到的 PID 逐字对得上 ⇒ **一次抓取 + 核标题**就能定帧的归属。
