# 批 69 · 代价探针的看门狗（2026-10-09）

## 0. 这一批改了什么

一颗探针 + 两把尺子 + 三处台架自己的缺陷（`app/` 零改动、屏上行为零改动）：

- `desktop/src/main/kotlin/com/venera/desktop/BlurCostProbe.kt`：每一相的「起手等待 → 预热 → 回起点 → 正经采样」
  整段套进 `withTimeoutOrNull(FrameWaitMs + holdMs)`；超时念一行 `S09C_挂 相=N 等帧超时=…ms（会话不可见？锁屏？）`
  并以 **退出码 2** 收尸。门槛 `FrameWaitMs = 60000L`（对稳态那一档约 1.2 秒宽了 50 倍 ⇒ 报警只管"一帧都不出"，
  不误伤"真在画而画得慢"）。`+ holdMs` 是必须的：`-Phold` 那一档是给人拍帧用的，门槛不吃它就成了假报警。
- `desktop/src/test/kotlin/com/venera/desktop/DesktopBlurCostProbeTest.kt`：**15 ⇒ 17 条**（⑯ 看门狗在不在、
  门槛是不是常量、次序、报警带相号与门槛；⑰ 挂了必须当场收尸 —— 报警 → `exitProcess(2)` → 才轮到收读数 → 判词 → `S09C_DONE`，
  两支退出码各恰好一处，报警段里不许出现成功收尾）。

## 1. 为什么这一批属于"基础框架"

批 68 那一跑 `-Pstep=400` 起了窗、念完 `S09C_相0起手` 之后**十分钟零输出**：进程活着、窗口开着、什么读数都不念。
成因是会话不可见（锁屏）时 `withFrameNanos` 根本不返回 —— 帧时钟不走。当时 15 条判据全绿：
**它们钉的是"探针代码写没写对"，从不跑真探针** ⇒ "全绿"与"这一跑什么都没量"能同时成立。

⇒ 量具至少要能说出自己没量到东西。这一批把这句话说成了代码里的一行读数和一个非零退出码。

## 3. 台架自己有三处坏（本批真正的收获比那两把尺子大）

1. **`report` 那支掉错了分支**：`_qa/b69_perturb.js` 把 `report` 也走了"取序号 → 查 PETS"那段，
   于是每笔只念「没有第 undefined 笔」而**退出码 0**。整张扰动表看着跑完，实际一笔红都没记。
   ⇒ 驱动现在逐笔把 report 落到自己的 `_qa/b69_r<N>.report.txt`，没念出 `RED`/`BAD` 就 `REPORT_EMPTY` 停下 ——
   而且停下之前**先还原**（第一版是 `break` 直接退出，把改坏的文件留在树里）。
2. **`node … check | tail -1 | tee -a … || exit 1` 的退出码被管道吞了**（本机这一族第三次）：
   锚点不对时驱动照样开跑。⇒ 改成先落文件、单独取 `$?` 再判。
3. **后台任务"停了"不等于停了**：两次 `TaskStop` 之后 `_qa/who_is_cycling.ps1` 仍数到一枚活着的
   `sh.exe _qa/b69_perturb.sh`，它一边循环一边改那颗探针，与我手上的手动还原互相踩 ——
   于是出现过"锚点检查刚念全齐，下一眼 R4 已被改坏"。⇒ 驱动加了一把目录锁 `_qa/b69_perturb.lock`（`mkdir` 原子、
   `trap` 收尾删），那枚 ps1 的匹配从裸 `perturb` 收紧成 `_perturb\.sh`（裸匹配会把**问这句话的那颗 shell 自己**也算进去，
   带 `-Kill` 时就是在杀调用者）。以后跑台架一律前台。

## 4. 重载那一格的**第一笔真读数**（判词那行第一次带着数据念出来）

`sh gradlew :desktop:blurcost --offline -Pstep=400`（会话这次可见，帧时钟在走，看门狗一次没响）：

```
S09C_相0 糊=off p50=5.58 p95=9.68 max=11.21 丢帧=0/179
S09C_相1 糊=on  p50=5.57 p95=9.93 max=17.88 丢帧=1/179
S09C_相2 糊=off p50=5.57 p95=6.67 max=20.14 丢帧=1/179
S09C_相3 糊=on  p50=5.59 p95=10.03 max=17.78 丢帧=1/179
S09C_差值 p50 +0.00ms(1.00倍) p95 +1.80ms(1.22倍) 丢帧 +1 帧
S09C_回退 两相不糊相比（序偏置）p95 -3.01ms 容差=2.00ms 判定=这跑不可比
S09C_重复 两相糊相比 p95 +0.09ms
S09C_判 差值|p95|=1.80ms 噪声地板=3.01ms 判定=量不出（差值没盖过噪声地板；这一格今天仍未知）
```

读数说的事，逐条分清：

- **判词落在"量不出"**，而且落得有理：地板 3.01ms 全部来自序偏置那一枚自比（相 0 比相 2 慢 3.01ms），
  糊组自己两跑只差 0.09ms（这组内重复性极好）。日志留档 `_qa/b69_cost400.log`。
- ⚠️ 这一笔顺手暴露了配对设计的一处**没想到的地方**：批 65 的算法假设"起步惩罚在两组里各占一半"，
  实际上四相里起步只落在**相 0** 那一相（不糊组）。方向是**对糊不利**（把不糊组抬高 ⇒ 差值被压小），
  所以真实的糊代价可能比 +1.80ms 还大一点。⇒ 这不是"已验无代价"，也还不是"已验很贵"。
- 下一件（批 70）因此有了明确形状：把起步那笔惩罚从"分摊"改成"扔掉" —— 在四相之前先跑一相**丢弃相**
  （或不改变采样数、把 `PHASES` 换成 `off,on,on,off` 让两端各一组），再把 `S09C_回退` 的容差那枚数与判词
  的地板合起来看是否终于 `量得出`。改的只有那颗探针与它的尺子，`app/` 照旧零改动。
