0三句话结论

① 根因是「压 maxHeight」，不是「摆放方式」
上一轮只把 Modifier.height 换成 layout{} + place(0,0)， 却没动那条 maxHeight ⇒ 挤压照旧。真机量化：旧包 134px、 新包 132px，几乎没变 —— 这就是"还是没居中"的原因。换摆放方式 ≠ 放开测量约束，两件事必须一起做。
② 真正错位的是右钮，不是标题
自绘「画廊」一直落在 188px（与 8 张普通页截图完全一致的基准）， 是 miuix 那两枚胶囊被上顶到 132px，差 54px ≈ 21.2dp。 前两轮把因果搞反了：标题的位置一直是对的。
③ 顺手把基准改成「与 miuix 同源」
旧写法自己读 WindowInsets.statusBars 再算 Dp；本机两份 inset 数值 恰好相等 ⇒ 缺陷隐身在"看起来对"里，尺子也量不出来。改成挂 miuix 自己那一个表达式， 把"同线"从巧合变成同源。

2根因：Constraints.maxHeight 是「挤压」，不是「裁切」

miuix 的 TopAppBarLayout 用 constraints.maxHeight 去测量内部所有子件， 然后自己 layout(constraints.maxWidth, layoutHeight) 报高 —— 报高不看 maxHeight （TopAppBar.kt:892）。于是"压 maxHeight"的实际效果是：

报出来的高度一点没变，但内部子件被居中上顶 (自然高 − 允许高) / 2。
项算式数值
miuix 本体自然高inset + layoutHeight
layoutHeight = barHeight(52 + expansion) + LargeTitleBottomPadding(4)		 49.2 + 94.4
= 143.6dp
钉的允许高inset + CollapsedHeight49.2 + 52
= 101.2dp
被上顶(143.6 − 101.2) / 221.2dp ≈ 54px

那个 expansion（≈38dp）不是别的东西，就是空大标题占的一整行： largeTitle 的 Box 自带 padding(top = CollapsedHeight)， 所以即使传空串也照样占一行字体度量。我们钉高度时把它算了进去、却没给它位置 —— 它就把整棵子树顶起来了。

为什么上一轮会白改： 把 Modifier.height(pinnedBarHeightPx) 换成 layout{} + place(0, 0) 只改了摆放方式，测量时那条 maxHeight = pinnedBarHeightPx 还在 —— 挤压链条一个环节都没断。真机上两版读数 134 vs 132，正是"几乎没变"的量化证据。

3修法：把测量高度完全放开，让外层裁

唯一改动的产品代码在 VeneraTopAppBar.kt 的 if (pinCollapsedHeight) 那一支：

// 修法：把高度**完全放开**（Constraints.Infinity），让它按自然高报出来；
// 多出来的那一整行空大标题交给外层 clipToBounds 裁 —— "钉成折叠态高度"
// 照样成立，而 miuix 内部那套 insets padding + verticalCenter 一点不动，
// 于是它的 actionIcons 落回 inset + 26dp，与自绘小标题**同一条线**。
.layout { measurable, constraints ->
    val placeable = measurable.measure(
        constraints.copy(minHeight = 0, maxHeight = Constraints.Infinity)  // ← 本轮唯一实质改动
    )
    val width = if (constraints.maxWidth == Constraints.Infinity) {
        placeable.width
    } else {
        constraints.maxWidth
    }
    layout(width, pinnedBarHeightPx) { placeable.place(0, 0) }
}
.clipToBounds(),
为什么这样就对了：约束一放开，miuix 就按自然高（143.6dp）报出来、内部一切按它自己的 insets padding + verticalCenter 落位 ⇒ 右钮回到 inset + 26dp。 我们只把外框钉到 101.2dp 并 clipToBounds 裁掉多出去的那 42dp —— 那是空大标题的空白区， 裁不掉任何内容（这一路判据里 largeTitle 恒为空串）。
注意这两件事必须成对：「钉成折叠态高度」= ① 放开测量（Infinity）+ ② 自己裁 （clipToBounds）。只做 ① 会让顶栏虚高一整行、背板跟着回到旧高度；只做 ② 就是本轮修掉的挤压。

4顺手订正：自绘小标题的基准改成「与 miuix 同源」

miuix 的标题行与按钮行都落在 windowInsetsPadding(WindowInsets.systemBars.only(Top)) 之内 —— 那个 padding 挂在这颗 Layout 自己身上（TopAppBar.kt:806）， verticalCenter = collapsedHeight / 2 从 inset 之后起算（:881）， title 与 actionIcons 同式落位（:906 / :920）。 所以那一行的绝对中心 = inset + CollapsedHeight/2。

局部量也一并改名并跟随 miuix 读同一份：
