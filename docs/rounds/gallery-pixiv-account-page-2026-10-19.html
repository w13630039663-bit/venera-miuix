pixiv 个人账号页 · UI 方案

2026-10-19 · 画廊模块 · 一套定稿 · 只画稿，一行 Kotlin 都没动

入口：画廊首页顶栏左上角那颗头像（GalleryPixivAccountButton，那颗件已存在）

这一屏不是新造一屏。它是把已有的三样东西按你给的三张截图那个顺序摆到一起 —— 画师页的头部（PixivArtistScreen）、云端书签墙（GalleryPixivBookmarksScreen）、 关注列表那条腿（/v1/user/following）。真正缺的只有「动态」这条腿和「非公开」那一档。

为什么分段挂顶栏、头部跟着滚：本仓 2026-09-27 已有一条拍板 —— 收藏页那枚二级分段器必须挂在顶栏 chrome 上，不跟着内容滚。这一屏三段是同一类东西（切的是"读哪一趟"， 不是"看到哪儿"），所以同一条规矩。头部（hero + 头像 + 四个数）跟着滚走，理由与画师页那条逐字相同： 三段都长，钉住会吃掉 200~300dp 浏览高度。

1三屏定稿

同一颗顶栏（主行 52dp + 分段行 38dp，全在玻璃 chrome 里）、同一条内容滚。 三屏只差内容区那一段：动态与收藏是墙，已关注是画师行。

  1. 顶栏主行 52dp（topBarCollapsedHeight）：返回 pill（VeneraTopBarPill，视觉 40 / 触达 48） + 30dp 小头像 + 名字 + 右端那一枚 restrict 下拉。整条挂玻璃（backdrop 取下方内容， 滚过 hero 之后自己补底）。小头像在顶栏里不可点 —— 已经在这一屏了。
  2. 分段行 38dp（pixivFollowPillHeight）：轨道 surfaceContainerHigh + 选中白胶囊 surface，与画师页 PixivSectionRow 同一颗形状。钉住不滚（09-27 那条拍板）。 数字是真数（/v1/user/detail 的 total_*），取不到就不带数字 —— 那一格不摆 0。
  3. hero 190dp 只在「我发布的」那一档摆（§2 的 ④）：满幅 = 站方自设背景 background.url（1920×960 档，天然横图，Crop 几乎不裁）； 没设置退回首张作品；都没有 = 一块 surfaceContainerHigh。定高由断点驱动，不跟图比例（平板另有档）。
  4. 头像 76dp（同样只在 ④ 摆，pixivArtistAvatarSize）压进 hero 38dp，2.5dp 页面底色描边环 —— 压在照片上没有环就糊一圈。右端那颗是在 pixiv 打开（站方原页的正当出口：看小说、看约稿、看全部收藏）， 不再是退出登录 —— 退出挪进下面那一节，见 ⑦。
  5. 四格数据行（也在 ④）来自 /v1/user/detail 的 profile.total_*； 取不到的格退「—」，不拿 0 顶（0 是断言，— 是不知道）。
  6. 卡上那一行就是应用里现成的那颗：GalleryCardCaption 的「头像 + 两行」那一档 —— 24dp 圆角方头像（shape.small + 描边环，点脸直通画师页）+ 标题一行 + 画师名，与 pixiv 推荐墙、云端书签墙同一颗件，不另画一种卡。心形今天只是读数，点它 = 写侧，要等 §9 的写腿点头才挂上。
  7. 墙：两列瀑布流（gridGap 12 / 屏边距 screenHorizontal 12 / 封面圆角 shape.medium 14）， 与书签墙、画师页同一颗 buildGalleryWall：打码、屏蔽规则、AI 过滤同一把尺。 心形吃 actionFavorite（MIUIX 档是紫，不跟截图那枚红）。
  8. 二级那一行（只在动态段）：我发布的 / 关注动态 / 账号管理。 登录态、票据新鲜度、粘贴凭据、退出登录全部收进「账号管理」那一子页（§2 的 ⑤）， 头部不再挂账号节 —— 头部只留"这是谁 + 四个数"，退出这类操作不该在每一段的第一屏上占 100dp。 本机 Google 那一行已经整条撤掉（§9 的 ⑤，2026-10-19 当日落地）：登录弹层里那一块、 那句「不等于 pixiv 登录」的护栏与 PixivLoginPathsTest 里钉它的用例一起走。
  1. 私密档常驻那一行：选了「非公开」时钉在内容第一行，不涂不透明底（玻璃顶栏内联区那条老约束）。 不点名会让"非公开"读成"加载了另一种排版"。
  2. 书签标签行已拍板不接（/v1/user/bookmark-tags/illust）：整行不摆，顶栏那枚 # 也不摆。收藏段只有两把条件 —— 公开/非公开，以及往下滚。
  3. restrict 下拉弹层见 §4。三档里「全部」是两趟合并 + 按 illust_id 去重，页脚要按趟说话。

2「动态」拆三档子页：我发布的 / 关注动态 / 账号管理

二级挂在一级下面那一行（30dp 自持药丸，比一级低一档，不与它抢重量）。 只有「动态」段有这一行 —— 收藏与已关注那两段本身就已经是一档内容，再加二级是空转。

  1. 「我发布的」这一腿已有：userIllusts(bearer, userId, type) → /v1/user/illusts， type=illust / manga（画师页那条腿，换自己的号）。 但「非公开」那一档站方是不是同一枚 type 参数给的，本仓没有读数 —— 稿上那枚「非公开」角标 画的是站方回字段里的档（xRestrict），落地时先现量再钉，别按推断接。
  2. 「关注动态」与「我发布的」是两趟不同的请求（/v2/illust/follow vs /v1/user/illusts）， 切子页=换腿，不共用缓存、不叠在一起。这一档没有 hero 的必要，但为了切子页时头部不跳， 三档里前两档共用同一个头部（只有墙换）；「账号管理」整屏换成表单，头部与 hero 一起撤 —— 它没有"一个人"要看。
  3. 账号管理这一子页顶栏少一枚：restrict 那枚下拉在这里没有作用对象（它管的是"读哪一趟内容"）， 所以那一格空出来，主行只剩 返回 + 小头像 + 名字。范围设置改以一行「默认范围」出现在这一页里 —— 两处读数是同一个键，不是两个开关。
  4. 「非公开内容」那一行是这一屏唯一的总闸：关掉之后 restrict 下拉退成两档（公开 / ——）， 私密档不发请求、也不出现在任何计数里。这一条是 §3 注 ② 的护栏：界是他划的，也要能一键擦回来。

两条要先说清的

① 截图一那种「一位画师 + 三张作品 + 已关注钮」，pixiv 没有一条腿能一次给全。 /v1/user/following 只回 user_previews（头像、名字、is_followed），不带作品； 三张封面得为每位再发一次 /v1/user/illusts?type=illust&per_page=3 —— 一屏 4 位 = 4 跳， 串行会慢到能看见，得并发 + 每位到货即填那一行。已拍板：真拿三张低清预览（站方 square_medium 250×250 那一档，与卡上现有预览同一档，不另取原图）；取不到的那位那一格退成只有头像与名字的一行，不摆空框、也不拿别人的封面顶。

② 「非公开」这一档本轮是改口径，不是补功能。 bookmarkIllusts() 的头注现在明写着「private 那一档不接：不是取不到，而是私密书签是用户给站方划的界」。 这次是号主本人要读自己的私密档 —— 界是他划的、也由他擦，屏上仍常驻那一行点名（§1 的 ⑧）， 且绝不把私密档混进任何会被别人看到的墙（首页、收藏 hub、分享出去的读数都不含它）。已拍板：接。落地时把 bookmarkIllusts() 与 following() 的 restrict 从写死改成形参、默认值仍给 public，书签 hub 那一屏与画师页的收藏段因此零回归；这条改口径同时改那颗件的头注，别留一句反着说的话在代码里。

4restrict 那一枚下拉（顶栏右端）

  1. 为什么是下拉而不是第三行药丸：顶栏已经有两行（52 + 38 = 90dp），再加一行 32dp 就吃掉 122dp， 首屏的墙只剩两行半 —— 那正是「每行都在抢内容高度」那条老账。收成一枚，读数仍然在屏上（那两个字就是当前档）。
  2. 弹层用 VeneraDialog 还是 Popup 由宿主定：这一屏没有 miuix Scaffold 的场合要退到 WindowDialog（那条既有拍板：没有宿主就别用 OverlayDialog）。
  3. 「全部」这一档如果 §9 的 ③ 拍板不接，这一枚就退成两档切换（公开 / 非公开）， 与截图一、二一致 —— 截图三那枚「全部」是站方给的，不是我们必须给的。

5退出这一档：点一下先问一句

退出会清掉这台机器上的凭据（PixivCredentials.signOut()），是这一屏唯一的破坏性把手， 所以两步：那一子页里那颗「退出」只开确认，真退出在确认里。站方那一份（收藏、关注、书签标签）一行都不动 —— 这句话必须上屏， 它今天就在原来那颗弹层里写着，搬过来不改词。

  1. 为什么不留「这是谁」那颗旧弹层：它问的两件事（我是谁 / 要不要退出）现在是「账号管理」那一子页的两组行标题， 弹层成了多一跳的重复。撤掉之后 GalleryPixivAccountButton 的已登录分支只剩导航。
  2. 「重新登录」那颗恒可点：它开的是登录弹层那条正常路径（浏览器 / 粘贴两路）， 与 §6 的 S3 那档「票据过期」说的是同一句话，两处不各写一遍。
  3. 这一节的三行都是账号维度，没有一行是内容设置 —— 屏蔽规则、列数、AI 过滤那些仍在设置页， 别顺手搬进来（搬进来这一节就变成第二个设置页，且与设置页两处读数不同步）。

6状态矩阵（每档说什么，不许混）

这一族最容易塌成同一句"没有内容"。下面六档句式互不相同； 「没登录 / 票据过期 / 站方挡下 / 老记录没存用户号」四档绝不合并 —— 合并了用户就不知道该点哪儿。

另三档（写法同上，稿上没画）

S4 这一段真的空：「这个账号一件公开收藏都没有」—— 与 S3 的区别是不摆按钮 （按下去还是同一句话就是假开关）。

S5 续页失败：页脚一行「下一页这一回没取上 · 再划一下重试」，已取到的留着（按一下等于删一屏，那是另一种伤）。

S6 老登录没记下用户号：bookmarks/illust 与 following 都要 user_id， 老版本写下的记录里没存这一格。这一档与 S2 分开念 —— 顶栏说"已登录"、这一屏不能说"你还没登录"，两句话会打架。

9拍板结果（2026-10-19）· 与不做的

已拍板 · 七条

① 「非公开」接 —— 推翻 bookmarkIllusts() 头注里那条旧裁决。 restrict 落成一枚必填枚举形参（PixivRestrict，故意不给默认值）： 默认值会让"漏传"重新变成编译期看不见、运行期只表现为默默按公开答，那正是假读数那一族。 书签 hub、画师页、首页关注那一栏三处调用点各自点名 Public，零回归（§3 注 ②）。

② 已关注那一屏真拿三张低清预览 —— 每位再发一跳 /v1/user/illusts， 并发 + 到货即填那一行；取不到的那位退成只有头像与名字的一行（§3 注 ①）。

③ 「全部」这一档留 —— 两趟合并 + 按 illust_id 去重，页脚按趟说话 （站方没有"两档都要"那一枚值，所以这一档是发两趟，不是传一枚更宽的参数 —— 判据在 PixivReadScope.legs）。

④ 书签标签行不接 —— 整行不摆，# 那枚也不摆。

⑤ 本机 Google 登录撤掉（已落地）—— 登录弹层里那一整块（按钮 + 护栏那句）一起走， PixivLoginPathsTest 那四条用例与三颗账号件一起撤（§7）。

⑥ 「我发布的」不分插画 / 漫画两桶 —— 一面墙，卡上带 manga 角标。

⑦ 收藏 hub 那枚 🔖 改跳账号页的收藏段（已落地） —— GalleryPixivBookmarksScreen 收成账号页里的一颗共用件，不留两个入口两套读数。

本轮不做

写侧：在自己的账号页里关注 / 取关 / 加书签 / 撤书签 —— 站方写腿已有 （followAdd / bookmarkAdd），但要单独点头，且要有回滚与 401/403 两句不同的话。 稿上「已关注」那颗 pill 是读数不是把手（点了没反应不对，所以那一档要么接写、要么整颗退成不可点的文字）。

小说：站方有 /v1/novel/* 一族（pixez 也接了），本仓没有小说屏。

沿用不改：卡片墙、打码与屏蔽判据（buildGalleryWall）、列数尺子、波浪环、玻璃顶栏 —— 同一张图在首页、画师页、账号页三处必须同样遮或不遮。

桌面档：这一屏只在 Android 画稿里出现。:desktop 那侧要不要同一屏、 以及 pixiv 票据在桌面能不能取到，是另一轮的事。

这份稿只画观感，不证明能力。§3 表里标 缺 与 半 的四条腿， 落地时要按本仓规矩带日期现量一遍（公开 / 非公开两档各打一次），别把 pixez 的形状当成我们的读数。

11真机五屏对稿后的重做（2026-10-19 晚）

真机读数（截图里看得见的偏差）

  • 同一个名字在一屏出现三次：顶栏大标题、hero 头部、账号管理身份卡。
  • 顶栏副标题写着「含非公开」—— 读起来像这一屏的标题叫这个名字。
  • 一级三颗与二级三颗都是描边药丸，同宽同重，一级二级分不开；稿上是"轨道 + 选中白胶囊"。
  • 「我发布的」头部没有 hero、没有压边头像、没有四格读数；名字与账号是裸文字。
  • 「已关注」三张预览挤在行尾，竖 / 方 / 横参差成锯齿，第三张贴到屏右缘。
  • 账号管理三行右端全写「打开」，包括退出登录那一行（假把手）。

按稿改回来的

① 主行报屏名「我的 pixiv」；画师名只在内容里出现（hero 头部与身份卡各一次，属两处不同语义）。为什么不做稿上那条紧凑主行：VeneraTopAppBar 的 pinCollapsedHeight 支路会把 bottomContent 裁掉，而这一屏的两行分段器正挂在 bottomContent 里 —— 照稿压主行会连两行分段器一起消失（已读源码确认，不是推断）。

② 顶栏副标题撤掉；「这一档包含你标为非公开的收藏与关注」改成内容第一行那一条（锁图标 + 一句话），只在墙这一支出现。

③ 一级 = PixivAccountSegmentTrack（surfaceContainerHigh 轨道 + 选中白胶囊 + 真计数）；二级 = 只描边的 PixivAccountSubPill（选中才染 12% 主色，计数只在「我发布的」）。两行都按稿留 12dp 屏边，二级行与轨道之间留 8dp、收尾再留 8dp，三颗按 weight(1f) 三等分（稿里的 .seg / .sub2）。让位那笔账逐节对着实高写：轨道 + 8 + 二级行 + 8 —— 从前少算后两节，内容第一行就被药丸压住了。

④ restrict 从药丸改成「锁 + 档名 + ▾」，进 actions；总闸关掉时下拉只列公开一档（不灰着摆假选项）。

12二轮真机：留存 · 下拉才刷 · 横滑 · 实底顶栏 · 背景不糊 · 按钮加高（2026-10-19 晚）

用户六条原话：「1 所有界面都加上数据持久化，退出应用前切屏幕都要留住数据，2 主动下拉刷新才重新获取新数据，3 页面支持左右切换加上一些，加上新页面从右侧滑入，旧页面向左滑出的动画 4自己看图，顶栏做成和目前软件顶栏一样的效果，不要透过 5.整个页面背景怎么是模糊背景 6.大按钮太矮了」。

真机读数（那张 1080×2376 截图）

  • 大标题「我的 pixiv」压在一排未模糊的卡片上 —— 顶栏是玻璃、内容从底下穿过去。
  • 一级药丸的下半截被网格第一行压住 —— 顶栏让位只按主行算，没算 bottomContent 里那两行。
  • 整页背景是粉色的模糊 —— Activity 挂着 blur-behind，窗口后面透出上一层界面。
  • 返回药丸也糊 —— 同一份窗口模糊。
  • 一级按钮 38dp，手指按上去像标签不像按钮。
  • 切段 / 切档 = 白屏重取 + 滚回顶部（上一批的 remember(requestKey)）。

六条怎么落的

① 数据留在进程里：新增 gallery/ui/PixivAccountSessionStore.kt —— 三面墙（我发布的 / 关注动态 / 收藏）、已关注那一列、身份读数（head + detail）各有一份进程级会话，连滚动 index + offset 一起存。仓用 SupervisorJob + Dispatchers.Main.immediate；ensure() 只发第一趟，切屏 / 旋转 / 离开再回来都不重取；取失败保留上一批内容；退出登录 clear() 清仓，旧账号的数据不挂到新账号下面。

② 只有主动下拉才刷新：首屏只 session.ensure(legs, fetch) 一次；之后只有 PullToRefreshBox 的 session.refresh(...) 与错误页那枚「重试」会再发（两条出路共用同一颗 refresh）。顶栏计数与 hero 的身份读数跟着下拉一起换新；重组、切段、切档都不发车。

③ 三段左右滑 + 方向化二级：外层 HorizontalPager（3 页，初始停在入口给的段）；点一级药丸走 pagerState.animateScrollToPage，手指左右划直接换页。二级三档不进 Pager（里层再吃横滑会抢手势），改用 AnimatedContent：新页从右侧滑入、旧页向左滑出；倒着切方向反过来，配 fadeIn/fadeOut 与 SizeTransform(clip = false)。换页落定后把顶栏折叠进度归零（settledPage，不是 currentPage —— 后者滑过半就变，会在半路把大标题弹出来）。

④ 顶栏实底：VeneraTopAppBar 新增 opaqueChrome，在顶栏 Box 内用 VeneraAmbientChrome 铺满整条（含 bottomContent）—— 与整页同一份 drawVeneraAmbient，只按宽度定位，接缝无痕；折叠行为与全站顶栏同一套，只是不透。本屏不传 backdrop、内容不挂 blurBackdropSource。三处可滚内容都接了 nestedScroll(topBarBehavior.nestedScrollConnection)，否则内容还是会从顶栏底下直穿。

⑤ 整页背景不模糊：VeneraSubActivityBase 新增 blurBehindEnabled 开关；本页 opaqueAmbientBackground = true（不透明氛围底）+ blurBehindEnabled = false；manifest 主题从 Theme.Venera.GlassOverlay 换回 Theme.Venera。窗口后面不再有上一层界面，顶栏与内容只共用同一份不透明氛围光。

⑥ 大按钮加高：一级 pixivAccountPrimaryRow 38 → 48dp，二级 pixivAccountSecondaryRow 30 → 38dp；两级的让位表达式跟着换，动态段仍多算一行二级。
