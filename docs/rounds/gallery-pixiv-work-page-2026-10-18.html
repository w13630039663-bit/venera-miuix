Pixiv 作品页 · UI 规划

一句话：打开一张 pixiv 作品，先在原地处看图，往下滑就把画师 / 标题 / 标签 / 推荐一并读完，不用退出播放器再进详情页。 底层（取图、缩放、手势、缓存、下载、收藏写口）整条沿用现成件，上层只新做这一屏的编排。 横向多图 = pager；纵向详情 = 外层滚动；操作栏 = 浮在屏底的玻璃条（不排在推荐之后）；连读模式 = 同一批页换一种排法，不是另一条取数路。

底层 · 原样复用（零改动）

  • 取图与缓存（Coil 管线、缩略/原图两档）
  • 缩放与手势（zoomable 层、双指/拖动）
  • 下载写口、收藏写口（含 pixiv 站方同步）
  • 卡片面（VeneraCard / 角标胶囊 / 站标）
  • 玻璃圆座（VeneraTopBarPill）、顶栏折叠那套

上层 · 这一屏新做

  • 作品页编排：pager 段 + 详情段同处一条滚动链
  • 多图进度两种说法：页码胶囊 + 缩略条（可折叠）
  • 底部悬浮玻璃操作栏（5 枚 + 分隔）
  • 纵向连续阅读档（与横向 pager 一键互换）
  • 相关图片三列网格（同标签 / 同画师混排）
  • 评论整屏（只读：头像 / 附图 / 表情 / 回复）

口径 · 尺寸全部取现成 token

  • 页边 screenHorizontal 12dp、行内 cardContentPadding 8dp
  • 圆角 shape.extraLarge（MD3 28 / Miuix 30）、卡 shape.card 16dp
  • 字阶 type.itemTitle 16sp / body 14 / caption 12 / badge 10
  • 胶囊高 filterChipHeight 32dp、动作位 sheetActionHeight 48dp
  • 底栏 bottomBarHeight 64 + bottomBarBottomGap 12 ⇒ 留白 bottomBarClearance 76dp

二 · 标注对照

1 图区：按真实比例摆，竖长页封顶 屏宽 × 1.2，超出部分靠缩放看全；两侧留白用同图模糊垫底（复用 artistHeroBackdrop* 那对 blur/scale 口径）。
2 画师行：头像吃 iconButtonSize 40dp（与顶栏圆座同档，不造新数）；「关注」吃 filterChipHeight 32dp；已关注态换 surfaceContainerHighest 而不是压主色透明度。
3 标签头：收起态只给一行 + 计数，点开拓成整墙；译名开时中文在上、日文原文在下（描边胶囊区分"这是原文"，颜色不是唯一说法）。
4 操作栏：外壳 64dp 高 + 距屏底 12dp（bottomBarHeight / bottomBarBottomGap），内容底部留白读 LocalBottomBarClearance；每枚视觉 40dp / 触达 48dp。
5 标签墙：胶囊间距 chipSpacing 8dp、内衬 chipHorizontalPadding 12dp；命中"屏蔽与过滤"里那条规则的标签照常打码，不在这里另立一套。
6 相关图片：三列网格、格距 space4 8dp、圆角 shape.small 10dp，一屏先给 9 张（原「同画师」那一排撤了，画师入口在顶部那一行 + 关注钮）；卡面直接复用画廊卡（AI 角标与分级遮罩同一条规则），右下那枚数字是收藏数（同 GalleryCornerPill 口径）。
7 缩略网格：格与格 gridGap 12dp，选中态用 2dp 主色描边（同时抬不透明度，不靠颜色单独说话）。
8 连读档：页距 gridGap 12dp、进度线 1.5dp；顶部胶囊念「2 / 8 · 连读」，退出把手在左上（close 而不是 back，因为它改的是排法不是页面）。
10 评论入口：数据条里那一格改成可点的「评论 6 ›」（主色 + ›，颜色不是唯一说法）；dock 第二枚同样带计数，两处同一个数、同一个来源。
11 评论预览：详情流里只给两条带头像的摘要，点进整屏；预览不摆表情与附件图（那一屏才给全），免得同一屏两种密度。
12 评论项：头像吃 iconButtonSize 40dp；时间走 caption 12sp；附件图 64dp 一方（点进看图器）；表情计数走小药丸；嵌套回复缩进一层 + 2dp 主色左线，作者那条带「作者」标。
13 更多面板：行高吃 listRowMinHeight 48dp、圆角 shape.extraLarge；屏蔽那三行各自写进已有规则表（标签 / 画师 / 分级），撤回入口在「屏蔽与过滤」，这里不重复摆开关。
9 沉浸态：淡出用 motion.medium 220ms；页码保留（用户放大时最容易丢"我在第几页"）。

三 · 首屏高度预算（393dp 宽的手机）

块高说法
状态栏 inset≈30dp系统给，页面不写死
图区（含页码）≤474dp封顶式：min(图按比例的实高, 屏宽 × 1.2)
画师 + 标题行64dp头像 40 + 上下各 12
标签头（收起）44dp一行胶囊 32 + 上下 6
缩略条72dp缩略图 56 + 上下 8
操作栏占位（浮层）76dpbottomBarClearance，内容底部留白读它
⇒ 首屏"图 + 画师 + 标题 + 标签头"齐活，缩略条压线可见；推荐落在第二屏（与用户那句"继续向下滚动就能看标签与推荐"对齐）。

四 · 待你拍的三处

#1 沉浸淡出：放大看图时操作栏要不要消失？消失 = 图最大，代价是"下载/收藏"少一次可达。本鱼倾向消失、单击回，但这是观感账，你说了算。
#2 缩略条默认态：展开（挑页快，但首屏图被压到 330dp）还是收起（图大，挑页多一步）？稿①按收起 + 只露一条画，稿③是展开态。
#3 连读模式的边界：只做"本作品多页纵向连读"，还是顺手把"同画师接着读"也接上？后者要新的取数编排，不是同一批工作量。
#4 评论这一屏的数据面还没通（2026-10-18 现量）：匿名侧 /ajax/illust/{id}/comments、/ajax/illusts/comments/page/{id} 等四个形状全回 404，作品页本体 /illusts/{id} 也回 404；只有 /ajax/illust/{id} 给得到 commentCount（现量一枚 6 条、一枚 0 条，另有 commentOff 那枚开关位）。⇒ 评论列表要走登录腿才能喂饱，字段表（头像 / 附件图 / 表情 / 嵌套回复到底叫什么）必须拿账号现量之后再定，不照猜的字段画界面。稿⑦给的是"拿到之后长什么样"。

五 · 明确不做

不做评论 / 相关作品"算法推荐"那一块匿名接口拿不到，硬做就是假内容
不做页内跳转漫画阅读器那套（跨页预取、双向翻页）pixiv 作品页的"页"是同一作品的多张图，语义不同
不做点赞/ Bookmark 列表可见性管理写口只有 add/remove；改可见性等 pixiv 侧接口确认
不做"发评论 / 按表情 / 回复"三个写口评论屏只读；没有写口就不摆输入框（摆了就是假按钮）

稿内 hex 只为表达"浅色档的层次关系"，落地一律吃 VeneraColorTokens 的语义槽位；图标全部线性 SVG（不用 emoji 当图标）； 所有可点处触达位 ≥48dp；动效时长走 VeneraMotionTokens，并留 prefers-reduced-motion 的退路。
