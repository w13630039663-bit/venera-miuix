## 1. 这一格为什么会坏，以及为什么只管一半

**① 站方最常回的两种"看着像货其实不是"**是 Cloudflare 的过盾 HTML 与一枚 JSON 错误信封。
桌面从前只挡 0 字节（`bytes.isEmpty()`），所以那一串 HTML 会**被当成一页写下去**，
而盘上那一判吃的是"存在且非 0 字节" ⇒ 那一话从此"齐了"，而其中几页永远打不开。
这不是理论形状：本仓在画廊那一侧量过 567/403 与过盾页那一族（手册 §0 与 `docs/rounds/` 里那几批的读数），
过盾页混进字节流是这台机器的日常。

**② 对岸为这一格专门写过注释**（`DownloadManager.kt:440-446`）：
坏图会被"大小检查"短路跳过，于是**重试永远治不好** —— 它正是要在跳过之前读文件头才说得清"这一页到底是不是图"。
本批那颗判式 ④ 钉的就是它那张表（四档魔数 + `bytes.size < 12`）：**对岸改了表，桌面会红**，而不是继续吞。

**③ 本批只管"写入前"，不管"回头治愈"**。
"用同一道校验去重下历史坏图"要改的是**"这一页在不在盘上"那一判**（`present` 那份与 `desktopComicChapterIsComplete`），
而那颗是全仓唯一一把判齐尺子（批 96 立、批 97/98/99/100 沿用，三档口径并存而桌面只用最硬那一档）⇒
动它属于**改判**，要连着那四批的判式一起重定，另批办。
登记：`desktop-comic-page-magic-repair`（下一格候选）。
今天的净效果是**结构性**的：桌面从不写下非图像字节 ⇒ "自己写下的坏图"这一族从此为零；
剩下的只有用户手工放的、或旧版本写下的那些。

**④ 白名单不止 JPEG 是有理由的**：页名恒 `.jpg`（沿用对岸那一形）而站方常回 PNG/GIF/WebP。
判式 ⑥ 是这一条的对照组 —— 只认 JPEG 头会把好页挡在门外，那比收下坏页更糟。

**⑤ 两处现量差异，本批**不改**、但要登记，免得下一个人把"逐字回核"读成"两端同形"**（本批复量 `app/…/download/DownloadManager.kt`，逐行现取）：

| 格 | 对岸 | 桌面（本批之后） |
|---|---|---|
| 校验吃的是哪一串字节 | `:557` 在**去混淆之前**校验 `rawBytes`，`:563` 才 `descrambleJmImage` | 校验的是**将要落盘的那一串**（已去混淆） |
| 校验失败之后 | `throw IOException` ⇒ 外层那一圈 `attempt < 3` **重试同一页** | 抛 `IllegalStateException` ⇒ 那一趟整体失败，重试由调用点决定 |
| "这一页已在盘上"那一判 | `:444-446` `exists() && length() > 1024 &&` **读文件头再校验一次**；而 JM 混淆图**恒不跳过**（`!isScrambledImage && existingValid`）⇒ 每次重下即治愈 | `present` 那一份吃 `isFile && length() > 0`，**不读头** |
| 落盘那一步 | `:565-572` 先写 `.tmp`，`if (targetFile.exists()) targetFile.delete()` 再 `renameTo`（失败降级 copy） | 直接 `writeBytes` 到目标名（**非原子**） |

⇒ 由第 3、4 两行拼出一条**本批没覆盖的同形缺口**：桌面写到一半被杀会留下一颗半截 `.jpg`（非 0 字节），
下一趟把它当已有页跳过，而清单最终仍落 `complete:true` —— 症状与 §1① 那一族**逐字相同**，只是成因从"站方回了 HTML"换成"写没写完"。
登记成 **批 103 候选**（一并把 §1③ 那条 `desktop-comic-page-magic-repair` 吃掉，因为跳过那一判读头之后两格是同一格活）。
⚠️ 第 1 行那个差异**不是缺陷**：混淆后的 JPEG 头部仍带 `FF D8 FF`（本批包内那趟 89 页 `全=是` 是这条的实证），
两端校验的对象不同串而结论一致；真要统一，得连"校验先于去混淆还是后于"一起判，本批不动。

## 2. 判式（`DesktopComicPageMagicTest.kt`，6 颗）

1. **四档图像头都算图像**（JPEG / PNG / GIF / WebP 各一枚，逐档真跑）；
2. **短于十二字节一律不算**（空串、11 字节、以及"12 字节才算"那一格边界各断一句）；
3. **过盾页与错误信封都不算图像** —— 另含两条把这道闸的**边界**说清的：
   `FF D8 FF` 头而尾巴是 HTML **仍算图像**（这一档只看头部，整张好不好是解码层的事），
   而第三枚对不上就**不算**（魔数是逐档看的，不是只看首字节）；
4. **魔数表逐字回核对岸**（五枚锚点全从 `download/DownloadManager.kt` 的源码文本现取正则，含那道 `size < 12`）；
5. **坏字节那一趟抛错而不落盘**（抛 `IllegalStateException`、那句含 `页=1` / `不是图像` / `共=2`、
   第一页留着、那颗**不存在**、清单那一格**字面上**是 `"complete":false`）；
6. **非 JPEG 的图像照样收**（PNG + WebP 两页 ⇒ `Completed(2)` 且 `desktopComicChapterIsComplete` 说齐）。

⚠️ 判式 3 的第一版写的是"带 JPEG 头而整体是别的东西 ⇒ 不算图像"，**跑出来是红的** ——
那道闸按对岸那张表看的就是头部那几枚，是**题面错了**而不是实现错了 ⇒ 改的是题面，
并把"这一档管到哪一格"写进判式与注释里（免得下一个人再把它当成整图校验）。
