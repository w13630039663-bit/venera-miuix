## 2. 落地形状（每条都能回代码）

`gallery/data/DesktopRegionDecode.kt`
- `DesktopRegionDecoder.sizeOf`：只读头部拿尺寸，读不动交回 **null**（不是零尺寸的一张图，也不是抛）。
- `DesktopRegionDecoder.decode`：`setSourceSubsampling` + `setSourceRegion` 一起给，**交回尺寸与算式不符就抛**（`D_分块 没生效：…`）。
  这一条是本层的存在理由：`setSourceRegion` 在 API 上是**建议性的**，reader 忽略它、交回整图、且不报错 —— 屏上看着"分块生效"而一帧内存都没省。
- `DesktopRegionPlan`：`decodedSpan`（向上取整，与 reader 语义同轨）、`sampleFor`（2 的幂、**上界是源跨度**）、`of`（部分越界折回，整块在图外抛）。
- `DesktopVisibleRegion`：`fittedSize` / `contentRect` / `of` / `destinationRect` —— 裁的块与摆的位置**同源于一条算式**（两处各算一遍就是"摆歪了看不出来"那一族）。
- `DesktopRegionGain`：换轨划不划算 = 解出来的像素数 ÷ 底下那张在同一区域能给的像素数。**> 1 才换**。

`gallery/ui/DesktopRegionStage.kt`
- overlay 那一层：**不进 `.zoomable` 变换**（分块图本身已经是看得见的那一块，再吃一遍变换会错两回），盖在底下那层上面 ⇒ 分块没到位时屏上仍是它，**永远不留白屏**。
- 摆放走 `Modifier.layout` + `Constraints.fixed`（**纯像素**）；`offset` 那枚也是像素 —— 中途一版把尺寸走了 dp，两层单位不一致直接错位。
- 三档退化各一句：缓存没它 / 读不动尺寸 / 解这一档抛了；不换轨那一档也念 `D_分块 不换轨 增益=…`。

接线：`DesktopGalleryViewer` 取址**仍全文件一处** —— 旧尺子 `DesktopGalleryViewerTest` ① 把本批第二处取址判红了，
**改的是接线而不是账**（地址由外层算一次、递进 `DesktopViewerStage`）。

上半收尾时给下一批的开工单写着"补一枚 `--viewer-pan=` 种子，用真窗口量偏移"。**换了路子**：

② 尺寸写进**普通 var** 时 `LaunchedEffect(尺寸)` 永远只看得到首帧那个零 ⇒ 效果不重跑、`settled` 恒假（要快照状态才作数）。

### 6.2 于是帧 C 那句"符号错"是错的，而真缺陷在另一处

上半写的"`offsetX` 的单位或原点与本层假设不符"被上面那表推翻：**单位、原点、符号三条全对**。
那一帧真正的形状是**跨度算超了** —— `DesktopVisibleRegion.of` 从前用**未折边的两端**相减：
内容被顶到黑边那一档时，屏上只露出图的前 401 行，而它按 643 行去解、再把 643 行拉伸到那一条带上 ⇒
分块图与底下那张对不上（看上去就是"错位"）。修法两处：

- `of()`：**两条边各自先折进图内，跨度由折过的两端相减**；折完为空 ⇒ 抛并念出可见列/行；
- `destinationRect()`：**向外取整**（近边 `floor`、远边 `ceil`）。按最近取整会少盖 1 px，
  那一条 hairline 正是"两层接缝"，而这层存在的理由就是消灭它；多覆盖那一像素画的是同一份源像素，无害。

`NaN` 那一档不是理论风险：它就是量具第一版的读数。所以 `of()` 起手一条 `require(全部有限)`，
而 UI 那一层把"算不出这一块"包成第四句退化（旧写法只包解码那一步 ⇒ `of()` 抛出去会崩在 `LaunchedEffect` 里）。
