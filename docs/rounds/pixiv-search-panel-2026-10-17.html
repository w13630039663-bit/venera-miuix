方案 C · 卡内展开面板

触发：首页内容域切到 Pixiv（pixiv 不在来源轴上，所以这一档卡里没有那排分段器）。范围：展开的搜索卡。依据：GallerySearchArea.kt 实读 + headless 量盒高。

形态：点「筛选」，卡自己长出一块面板 —— 不遮罩、不跳转、不多一层。「标签部分 / 标签完全」仍在框里（D 那一刀保留），所以面板只有四段：收藏 / 作品 / 画面比例 / 发布时间。

卡高：收起 245dp、展开 429dp；而键盘在时可用高度是 423dp。多出来的 6dp 不是取舍问题 —— 面板一开就必须收键盘，跟 A 的抽屉同一条规矩。

代价照实说：面板开着的时候，补全与历史都不在（卡装不下）。所以收起时必须有一行条件摘要，否则关掉就忘了自己筛了什么。

二、面板怎么排

两列：左边一枚 44dp 的标签，右边是这一段的控件。竖排（标签在上、控件在下）看着更松，但四段要多花约 90dp —— 而这一屏的预算是按 10dp 算的。

段摆法为什么
收藏七档刻度尺，占满右侧 300dp七枚胶囊并排要 346dp，放不下；刻度尺还顺带说明了「这是递进的门槛，不是七个互斥选项」
作品三枚胶囊一行全部 / 仅动图 / 排除动图，互斥且只有三档，一行正好
比例四枚胶囊一行同上，四档
时间两枚日期格 + 四个快捷精确到日走系统日期选择；快捷是「近 7 天 / 30 天 / 1 年 / 不限」，覆盖九成用法

「重置全部」放在面板右下角、只在这一块里 —— 它不重置排序（排序常驻可见，重置它反而会让人找不到自己刚选的序）。

三、卡高与键盘

态卡高键盘在时可用 423dp
收起（有历史）245dp余 178
展开（面板全开）429dp超 6dp

6dp 是个很尴尬的数：它意味着「面板 + 键盘」在任何一台 873dp 的机器上都差一点点。所以规矩不是「尽量收键盘」，而是「点筛选先收键盘」 —— 与 A 的抽屉同一条，只是 C 更没得商量：抽屉至少还能压着键盘弹出来，面板压在卡里，键盘一在就顶到屏底。

收起面板时不把键盘弹回来

用户点「看结果」/再点一次筛选收起面板，此刻他要看的是结果墙，不是接着打字。硬弹键盘会把他刚改的条件挡在键盘后面。

四、收起时的那一行条件

面板关掉之后，屏上只剩一枚带数字的「筛选」钮 —— 那不够：用户记不住自己是筛了 500+ 还是 1000+。所以收起时把生效条件压成一行（32dp），每枚带 ×：

收起态 · 条件行 32dp 收藏 500+ 横图 标签完全

这一行是从 A 那儿借的，也是 C 唯一需要「借」的地方。标签模式虽然住在框里，改了档也要出现在这一行 —— 它是生效中的条件，不能在摘要里缺席。

C 最值钱的一条是最后两行：它不多一层，而且和这张卡从 9 月就在用的「同一块面长高」是同一句话。A 的抽屉再顺，也是这个页面里突然出现的一块浮层 —— 而这张卡一直是「自己变高」的。

六、落地要点

  1. 面板长在卡里，排序行下面：输入行是锚点（也是共享元素那一端），不能动；长在它下面，切域与开合都读作「这块面在长高」。
  2. 开面板 = 收键盘 + 收列表：两件事同一次动作里做完，用同一对 expandVertically / shrinkVertically（160ms）。列表不是「隐藏」，是让位 —— 面板关掉它原样回来。
  3. 筛选钮的双向箭头：收起时 ⌄、展开时 ⌃，与面板开合同步。数字徽标只数「非默认」的项（标签模式不算，它在框里）。
  4. 不新增任何尺寸 token：44dp 标签列取 space9 + space6，面板圆角取 shape.large，行距取 space7，全是现成的。

七、一条待定

面板展开时，要不要留一行补全？ 现在的画法是整块让位。另一种是留最后一行（44dp）在面板下面，好处是「边改筛选边挑词」不用来回关。代价是卡再长 44dp（473dp），而 429 已经贴着上限了 —— 我按「全让位」画。
