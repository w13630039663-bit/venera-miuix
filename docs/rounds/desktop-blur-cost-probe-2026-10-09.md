# 批 64 · 那一层糊的代价：量了（2026-10-09）

## 1. 这一批要答的那一句话

批 62 量到应用内模糊在桌面上**画得出来**，批 63 把它接成了真行为（浮层开着时 `Modifier.blur(18.dp)`
挂在底下那面墙那棵子树上）。两句之间少了一笔账：**这一层每帧花多少钱**。
手册 §17 第 5 项当时写着「⚠️ 别把这条写成『已验无代价』—— 今天没有任何一跑量过它」。这一批就是去把那句"没量过"消掉。

## 2. 量具的形状（`BlurCostProbe.kt` + 任务 `:desktop:blurcost`）

- **三相在同一进程里**：不糊 → 糊 → **再不糊**。前两相比出代价，第三相是回退校验 ——
  最后一相没回到第一相那一档就说明这跑不干净，那差值不许拿去算结论（判据 ①⑤）。
- **帧时刻从帧时钟取**（`withFrameNanos`），不是拿 `System.nanoTime()` 前后夹（判据 ③ 负向钉零次墙钟）。
- **每相各跑「设相 → 预热 40 帧 → 回到第 0 项 → 取 180 帧」**，钉的是次序不是"这几句在不在"（判据 ④）。
- **半径吃产线那一枚 `DesktopWallBlurDp`**（18dp），探针里不许自己造数（判据 ②，含"半径写成字面量"的负向钉）。
- **正对照的把手**：`-Pstep=<像素>` 把每帧推进调大（默认 40）。这一枚是**这批的关键** ——
  三相读数一模一样有两种成因："糊真的不要钱"与"这把尺子压根不认账"。没有把手就只能选一种信（判据 ⑧）。
- **`-Phold=<毫秒>`**：每一相起手真等，给 WGC 拍帧用（默认 0，取数那一跑不白等，判据 ⑦）。
- **屏上一枚自报家门的牌**（`相N 糊=on/off 半径 18dp 步进 40.0px`），挂在糊那层**外面**（判据 ⑨）。
- 瓦片是本机生成的 **4×4 硬边棋盘**，不是随机噪声 —— 噪声在 108dp 格子里被缩采样成一团软糊之后，
  "糊了"与"没糊"在帧上读不出差别（这条是头一跑踩出来的，见 §5）。

## 4. 三条量具知识（比结论更值钱）

1. **`p50` 是时钟节拍，不是代价读数**：七笔里 `p50` 全钉在 5.55~5.57ms（≈180Hz 的帧时钟），
   与糊不糊、与步进 40 还是 400 都无关。这把尺子认账的是**尾巴**（p95/max）：
   步进 40→400 把 p95 从 ~5.7-6.3ms 抬到 7.4-10.8ms，而 p50 一动不动。
   ⇒ 任何"帧间隔均值没变所以没问题"的说法在这台机器上都是假读数，代价类结论只认 p95/max 与丢帧数。
2. **回退校验抓到了一笔脏跑**：`hold 30s` 那一跑第一相 p95=7.81/max=15.77（睡醒后的头几帧被算进了稳态），
   差值 −2.12ms 看着像"糊反而更快"，而 `S09C_回退` 当场判"这跑不可比"。
   ⇒ 那一行的存在让脏数据自己出声，而不是留下一句错结论。
3. **堆那一枚不能做逐相对比**：无 hold 两跑是 18→24→29 / 17→22→27（一路涨），
   正对照三跑是 29→20→28 / 28→16→22（乱跳）—— 那是 GC 时机，不是糊的开销。
   ⇒ 这一层的堆代价今天**没有**量到，别拿那三枚数说事。

## 5. 图证：两帧，各自写着自己是哪一相

同一颗构建、同一扇窗（pid 50588 / hwnd 3935426），只换那一相：

- `相0 糊=off 半径 18dp 步进 40.0px` —— 棋盘格边**锐利**，牌在左上角可读。
- `相1 糊=on 半径 18dp 步进 40.0px` —— 整面墙**糊成一团软块**（格边消失），
  而那一枚牌**仍然锐利** ⇒ 同一帧里既证了"糊真吃到墙上"，也证了"牌在糊那层外面"。

⚠️ 头一跑（pid 49328）拍到的两帧与相号**正好相反**：一软一锐，而软的那帧来自 `糊=off` 那一相。
两处成因叠在一起：① 我按 `起手等待` 的秒数掐时间去拍，而取样比我想的快，A 帧其实落在别的相里；
② 瓦片当时是随机噪声，缩采样之后"糊"与"没糊"本来就读不出差别。
⇒ 修法不是把等待调长再赌一次，而是**让帧自己写着它是哪一相**（屏上那枚牌）+ 把图样换成低频硬边。
这条与"图证要老实读一遍字""读数要带是谁改的戳"是同一族：**取证对象必须自证身份，否则读数会漂到别人头上**。

## 6. 结论与因此不做的三件事

> ⚠️ **本节 §3 表里"10× 重载 +1.34~+1.99ms"那一句已被批 65 撤下**（改判见
> `docs/rounds/desktop-blur-overlay-phase-2026-10-09.md` §4）：那一版差值拿**相 0** 当基线，
> 而这台机器的相 0 恒最慢（序偏置 −0.18~−0.87ms，方向正好偏袒糊）。改成四相配对后，
> 重载那一档两跑反号（+1.76 / −0.42）而糊组内重复性 −1.3~−2.7ms 比组间差还大 ⇒ 那是噪声，不是代价。
> 本节"稳态那档量不出代价"的结论**没被推翻**（配对口径下仍是 −0.01~−0.43ms）。

- **稳态那一档（生产形状：浮层开着、墙在身后、慢滚）量不出这一层糊的代价**：
  p95 差值 −0.13~−0.65ms，全在两枚"不糊"相自己的散布之内；丢帧 0。
- **10× 重载下尾巴略微变长**（+1.34~+1.99ms，1.16~1.23×，三跑同向），
  但同一跑的 off-off 散布也有 0.64~1.40ms ⇒ 只能说**未见成倍代价**，不能说"零代价"。
- ⇒ **不换实现**（不改成"糊一张快照"），**不改屏上那两句**（标签与 caption 说的是画什么，不是花多少），
  **不写"已验无代价"**（§17 第 5 项那句警告照此销账：量过了，结论是上面两句）。
- 屏上行为零改动 ⇒ 交付包**不重打**（与批 62 同一颗口径）。

## 8. 下一件

代价这一格有了读数 ⇒ 那层糊从"接上了、没量过"变成"接上了、量过"。往下两条候选：

1. **§17 第 2 项那两笔用户手上一试的账**（滚轮真缩放 / 复制真落进剪贴板）—— 本 agent 量不到，只能等回执。
2. **动图那一层在糊之上的行为**：批 51 让**大图那一屏**的动图逐帧在播，而墙上（`§0` 那句）仍是静帧
   ⇒ 生产里"糊着的那棵墙"自己不会每帧变内容。真问题因此是另一形状：**浮层里的动图每帧在换，
   身后那层糊要不要跟着每帧重算**（若那棵墙被缓存成层、只有覆盖层重绘，就是"一次性的钱"）。
   这一档用同一架探针加一相即可量掉：把"每帧变的东西"从墙挪到覆盖层（墙静止 + 上面一枚逐帧动的方块），
   与 §3 的"稳态慢滚"两档合起来才盖住生产那两种形状。
