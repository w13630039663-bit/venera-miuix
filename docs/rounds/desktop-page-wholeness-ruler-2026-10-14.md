# 批 110 · 「这一页在不在」那三把尺子收成一把：跳过前先读头（方案，2026-10-14）

上一格是批 109（源没声明 `onImageLoad` 时取图那一路照对岸兜，rounds `desktop-image-load-capability-2026-10-14.md`）。
本批做批 102 收尾时登记、此后一直挂着的那半格 —— **「跳过前读头」**，而它真正的形状比登记时更宽：**桌面今天有三处各数各的"这页在不在"**。

## 0. 缺陷那一形（读数 + 逐行现量，不是推测）

对岸那一支把"跳过"写得很明白，`app/…/download/DownloadManager.kt:446-455` 逐字：

```kotlin
// 断点续下判定：文件已存在且**内容确实是图片**才跳过。
// ⚠️ 历史缺陷两连：①旧版本把混淆未还原的原始字节落盘；②显式 Accept-Encoding
// 导致 OkHttp 关闭透明解压，落盘的是 Brotli/GZIP 压缩包 —— 两类坏图都 >1KB，
// 会被大小检查短路跳过，重试永远无法治愈。
// 修复：跳过前读取文件头做魔数校验，非图片一律重新下载覆盖；
// JM 混淆图恒定不跳过（落盘前已去混淆，重下即治愈历史坏图）。
val isScrambledImage = ImagePipelinePolicy.getScrambleNum(realUrl) > 1
val existingValid = targetFile.exists() && targetFile.length() > 1024 &&
    runCatching { isValidImageBytes(targetFile.readBytes()) }.getOrDefault(false)
if (!isScrambledImage && existingValid) { downloaded++; …; continue }
```

桌面同一格的现量（2026-10-14，`grep -n` 可复核）：

| 哪一处 | 今天怎么判 | 出处 |
|---|---|---|
| 续跑时"这一页跳不跳" | `page.isFile && page.length() > 0L` | `DesktopComicChapterDownload.kt:231-234` |
| 「本机已下载」那一屏的「已下全 / 缺 N 页」与体积 | `page.isFile && page.length() > 0L` | `DesktopComicDownloadedList.kt:104` |
| 队列那一行念的 已写/应写 | 名匹配 `\d{4}\.jpg` **且** `length() > 0L` | `DesktopComicDownloadQueue.kt:109-115` |
| 那一话齐不齐（清单那档） | `"complete":true` + 数页 | `DesktopComicChapterDownload.kt:138` |

⇒ 三把尺子都是"名字 + 非零长度"。批 102 那道魔数闸只管**新写的字节**，管不到**已经在盘上的**：
闸装好之前落盘的那一类文件（过盾页 HTML、错误信封 JSON、Brotli/GZIP 压缩包）今天仍会被三处一致地当成"这一页有了"——
下载那一趟跳过它、屏上念「已下全」、卡上那枚念「已下载 N 话」，而阅读器打开它是一片破图。
**重试永远无法治愈**那句是对岸的原话，桌面同一成因。

## 1. 定档：一把尺子，三处共用，数字沿用对岸

抽一颗**新的 internal 纯件**（住在 `DesktopComicChapterDownload.kt`，与那三处同一批文件家）：

```kotlin
/** 盘上这一页算不算"已经有了"：名对、够大、头部确实是图片。三处判据共用这一颗。 */
internal fun desktopComicPageLooksWhole(dir: File, index: Int): Boolean
```

- 判式 = `file.isFile && file.length() > 1024 && desktopComicBytesLookLikeImage(head)`，
  其中 `head` 只读**前 12 字节**（`desktopComicBytesLookLikeImage` 认 JPEG/PNG/GIF/WebP 四档头部，
  而那四档的头全在前 12 字节内 —— 现有那颗闸本来就要求 ≥12 字节，两把尺子必须同一字节数）。
- **不新写第二颗魔数判式**：`desktopComicBytesLookLikeImage` 是批 102 立的那一颗（`:204`），
  跳过那一侧复用它，"写之前"与"跳之前"才是同一口径；再抽一颗就是第四种"齐不齐"。
- 只读前 12 字节而对岸 `readBytes()` 整份读：这是**故意的改进**而不是漂 —— 一次续跑要判 30×N 页，
  整份读会把 20 MB 的页全过一遍堆。要在判式里钉住"读的是前缀"，别让后人以为是随手加的。
- `> 1024` 这个数**照抄对岸**（本仓口径：观感与阈值用现成口径，不造新数字）。
  代价要写明白：**小于 1 KB 的合法页每趟都会重取**（对岸同样如此，它那句注释就是拿 1 KB 当坏图下界）。
  这一档不藏：判式里各钉一枚"500 字节的合法 JPEG 仍判不算有"的正断言。
- 对岸 `isScrambledImage` 那一半**不搬**，理由要落在文档里：桌面这一路在落盘**之前**就完成去混淆
  （`EngineSession.pageImage` 交回的是还原后的图，批 102 的闸校验的也是那一份），
  所以"历史上落过未还原的原始字节"这一成因在桌面**不存在**；搬过来只会让每一页永远重下。

## 3. 判式（新文件 `DesktopComicPageWholenessTest.kt`）

1. **行为**：合法 JPEG / PNG / GIF / WebP 头部 + `>1024` ⇒ 算"已经有了"（四档各一枚，逐字节桩）。
2. **行为**：同一名与同尺寸而头部是 HTML（`<htm` 那形）或 JSON（`{"` 那形）⇒ **不算**（这一档就是本批的病根）。
3. **行为**：头部对而长度只有 500 字节 ⇒ 不算（对岸那把下界，钉住"这是结论不是巧合"）。
4. **行为**：短读安全 —— 文件不存在 / 0 字节 / 名字不合 ⇒ 一律不算且不抛（三档各一枚断言）。
5. **形状**：四处消费点都改吃那颗纯件（纯件名在 `desktop/src/main` 里现数 **5** 处 = 1 声明 + 4 调用），而旧那形
   `.length() > 0L` 与 `.length() <= 0L` **两种拼法**在那三颗文件里都零处（防"只改下载那一处、屏上仍用旧尺"）。
   ⚠️ 这一枚最初只钉了 3 处调用与一种拼法，放过了 §9 那一处 —— 落地后加宽，两种拼法都禁。
6. **形状**：全仓只有**一颗**魔数判式 —— `desktopComicBytesLookLikeImage(` 的声明恰 1 处，
   而新纯件里对它的那一跳恰 1 处（防第五种"齐不齐"从这一批里长出来）。
7. **接线**：跳过那一支读的必须是**前缀**而不是整份 —— 钉 `readBytes()` 在那三颗文件里零处
   （对岸用整份读，桌面故意不抄，这一枚就是那条"故意的改进 != 漂"的证据）。

## 11. 顺手逮到的交付包真缺陷：`.bat` 里 `%2F` 会被 cmd 吃掉

包外那条判式跑完之后再量的（读数 `_qa/b110_pct_probe.bat`，cmd 亲跑）：

```
echo A1 %2Fmanga%2Fabc     →  FmangaFabc          ← 裸的：`%2` 被当第 2 个参数（未定义）吃掉，剩下 F
echo A2 %%2Fmanga%%2Fabc   →  %2Fmanga%2Fabc      ← 正确写法
```

⇒ **已交付的两枚双击入口跑的是错号**：`_qa/desktop-exe-2026-10-14-b108/try-empty-table-wake.bat:26`
与 `_qa/desktop-exe-2026-10-14-b109/try-goda-page-image.bat:24` 里那串 `--comic=%2Fmanga%2F…`

包内那两批的读数**没有受影响** —— 复验是从 bash 直接起 exe（`%2F` 原样进 argv），不走 .bat。
这一格就是那条纪律的又一次样本：**「launcher 我没双击过」不等于「launcher 能用」**。

修法与量具：
- 两枚已交付的 .bat 就地补成 `%%2F`（`_qa/b110_fix_bat.js`，保住 CRLF），复跑读数：裸的剩 0 处、`%%2F` 各 4 处；
- 新增闸门 `_qa/check_bat_percent.js`：扫 `_qa` 下所有交付包与 .bat（名字含 `probe` 的除外 —— 那些是故意写裸的），
  凡 `^|[^%]%[0-9]` 就点名。现跑：`ok 没有裸 % + 数字 ｜ 扫了 46 颗 .bat`（退出码 0）；
- 批 110 那枚新入口 `try-wholeness.bat` 从一开始就写 `%%2F`，并把"章目录 / 夹具两颗文件现在的字节数 / 对照组那一颗"
  三行念在屏上，用户双击就能自己核对参数递对没对。

⚠️ 写这批夹具时另撞到一格 batch 解析坑：`for /L %I in (1,1,30) do >>"f" echo %LINE%` 里 `%LINE%` 展开出来的

（判尺子只看头部是不是图像魔数，不看它长得像不像 HTML）。

## 12. 盘上夹具那一格改判：清单保持 `complete=true`

§5 原方案要把 `chapter.json` 落回 `complete=false` 再跑。落地时改判：**不动那一格**。
成因是 `desktopComicDownloadChapter` 开头那一句 `if (desktopComicChapterIsComplete(dir, expectedPages))`
会直接早退并念 `页=30/30` —— 清单写着 false 时这一判**本来就拦不住**，于是"坏页不算已有"这一格
在屏上看不出是谁的功劳。留着 `complete=true`，唯一还能拦住"已下全，一页都不取"的那道闸就只剩批 110 这把新尺子，
而起手那一格念 `页=28/30` 就是它的读数。⇒ `_qa/b110_pkg_fixture.js` 按这一条改过（并把它自己那句理由写在脚本里）。
