4过度滚动已修

根因：API 换代 —— 老写法自写下那天起就一直是空转

设置页那两处写的是：

// SettingHome.kt / SettingsComponents.kt —— 原样
CompositionLocalProvider(LocalOverscrollConfiguration provides null) { … }

而在 foundation 1.12.0 的源码里，这个 CompositionLocal 已经带 @Deprecated， 官方弃用文案原话指名了替代品：

「To disable overscroll, instead of LocalOverscrollConfiguration provides null, use LocalOverscrollFactory provides null」
两者是两个不同的 CompositionLocal 实例 —— provides null 写在哪一个上就是哪一件事。 写在旧的那个上，新的那个照旧拿平台默认值，表现出来就是「设了等于没设」。

修法两条路

位置做法为什么这么走
设置页两处 import 与 provide 一起换成 LocalOverscrollFactory 只换 provide 会编译不过；只换 import 就是空转。两边必须同进同退
画廊头图墙 GalleryCardsGrid.disableOverscroll → overscrollEffect = if (disableOverscroll) null else platformOverscrollEffect LazyVerticalStaggeredGrid 本身收 OverscrollEffect? 参数 ⇒ 组件参数是最短路径，不必再包一层隐式状态
⚠️ 条件调用 Composable 会崩。 rememberOverscrollEffect() 必须无条件先 remember 出来，再按开关在 if 之外取舍 —— 把它写进 if 的分支里就是条件调用 Composable。 
// GalleryScreen.kt · GalleryCardsGrid
// 必须无条件先取，再按开关取舍（写进 if 分支 = 条件调用 Composable = 崩）
val platformOverscrollEffect = rememberOverscrollEffect()

LazyVerticalStaggeredGrid(
    …
    overscrollEffect = if (disableOverscroll) null else platformOverscrollEffect,
)

// GalleryForYouScreen.kt —— 有头图才禁
disableOverscroll = hero != null,

2头图通栏已修

头图住在网格的 header item 里 ⇒ 会跟着吃到 contentPadding 的左右内缩。 设置页那头图摆在内容列之外（外/内双 Column），天然从屏幕边到边 —— 画廊这边只能自己把那一圈还回去。

⚠️ 不能用负 padding：Modifier.padding 对负值有 require 检查，会直接崩。 改用自定义 Modifier.layout 把绘制范围拓宽。 
// 关键：报告宽度仍是 constraints.maxWidth ⇒ 网格那一行的占位一点没变，只有绘制范围变宽
private fun Modifier.fullBleedHorizontal(inset: Dp): Modifier = layout { measurable, constraints ->
    val insetPx = inset.roundToPx()
    // 容器宽未知（无限约束）时不做通栏 —— 宁可少通栏也不要量出一个荒谬的宽度
    if (insetPx <= 0 || constraints.maxWidth == Constraints.Infinity) { … }

    val fullWidth = constraints.maxWidth + insetPx * 2
    val placeable = measurable.measure(
        constraints.copy(minWidth = fullWidth, maxWidth = fullWidth)
    )
    layout(constraints.maxWidth, placeable.height) {   // ← 报告宽不变
        placeable.place(-insetPx, 0)                    // ← 内容往左拉出去
    }
}

搜索条不通栏 —— 它是圆角条，左右本来就该有内缩。尺子里有一条负向断言把它钉住（通栏只许被头图用一处）。

3上滑标题不居中已修

量出来的「偏」在垂直方向

「画廊」二字的深色像素横向范围 x=[503,576]，中心 539.5 —— 正是屏幕正中（(1080−1)/2）。 所以水平没偏。偏的是垂直：标题中心 127.5，而右侧两枚圆钮的中心在 190。 二者本该落在同一条 verticalCenter 上（miuix TopAppBar.kt:906 用它落 title、 :920 用它落 actionIcons），差的 62.5px 恰好 ≈ statusBarTop / 2。

miuix 源码推出的两条叠加后果

① 顶栏高度停在展开态
barHeight = lerp(collapsedHeight, collapsedHeight + expansion, 1 − collapseFraction)， collapseFraction 由 scrolledOffset 推 ⇒ 连接不挂 ⇒ 恒 0 ⇒ 恒等于 collapsedHeight + expansion。
expansion 就是大标题那一行（largeTitle 的 Box 自带 padding(top = CollapsedHeight)）。
② 原生小标题永不出现
smallTitleVisible = collapsedFraction × 3f ≥ 1f ⇒ 同样恒 false ⇒ smallTitleAlpha 恒 0 ⇒ 屏上那个标题只能是 VeneraTopAppBar 自绘的那一份。
③ 自绘那份的基准错了
它居中在 [0, statusBarTop + CollapsedHeight]，而 miuix 那一行落在 insets padding 之内 ⇒ 高 statusBarTop / 2。

修法

// ① 自绘小标题的居中基准挪到状态栏之后
.height(statusBarTop + TopAppBarDefaults.CollapsedHeight)
.padding(top = statusBarTop)          // ← 新增：居中出现「状态栏之后」，与 miuix 那一行逐像素同位
.graphicsLayer { alpha = activeProgress.value }

// ② 覆盖进度路径把顶栏钉成恒折叠态
val pinCollapsedHeight = scrollProgressOverride != null && largeTitle.isEmpty()

if (pinCollapsedHeight) {
    Box(Modifier.fillMaxWidth()
        .height(statusBarTop + TopAppBarDefaults.CollapsedHeight)
        .clipToBounds()                    // ← 刚需，见下
    ) { VeneraTopAppBarBody(…) }
} else { VeneraTopAppBarBody(…) }
⚠️ clipToBounds() 不是装饰，是刚需。 miuix 的 TopAppBarLayout 内部是 layout(constraints.maxWidth, layoutHeight) —— 它不看 maxHeight，报出来的高度会超出这里给的约束。不裁的话那一整行大标题的空白区照样画出去， 钉高度等于白钉（而且背板 matchParentSize 也会跟着回到旧高度）。
判据只钉「有把握的那一半」：pinCollapsedHeight 里带了 largeTitle.isEmpty()。 万一将来有人拿覆盖进度配一个非空大标题，宁可退回现状，也不能把它静默裁掉。

顺带抽出了 VeneraTopAppBarBody：两个分支共用同一份参数表， 不然将来加一个参数只改一边，两路就悄悄分叉了 —— 这是本仓反复踩过的「两处各写一遍」形状。
