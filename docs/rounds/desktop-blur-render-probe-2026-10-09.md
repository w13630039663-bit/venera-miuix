# 批 62 · 应用内模糊在桌面上画不画得出来（S0-7 §六 欠的那一步，2026-10-09）

零产品行为改动（只加一颗探针 + 一个 gradle 任务）。这一批把批 61 留下的那格"没量"补成"量过"。

## 1. 欠的是哪一步

S0-7 量的是 **gate**：`BlurEffect.isSupported() = true`、两枚 `isRuntimeShaderSupported()` 都真、
`SkikoRuntimeShader` 构造成功。它自己写着「**gate 说 true 不等于画面对**，需要一次像素级/目视确认」，
那条挂在阶段 1 的壳层验收里，一直没人做。于是批 61 接 `galleryBackdrop` 时，`GLASS` 那一档只能画实心底，
并在标签上明说 —— 那时"应用内那条路"的状态是**没量**，不是做不到（坑 ㊝ 就是这么来的）。

## 2. 造法：两枚同样的棋盘，右边那一枚吃模糊

`desktop/src/main/kotlin/com/venera/desktop/BlurRenderProbe.kt`（跑法 `sh gradlew :desktop:blurprobe`）。
同一颗 `Board()` 摆两枚 8×8 黑白棋盘（每格 20dp），右边那枚外面套 `Modifier.blur(radius = 24.dp)`。

⚠️ **为什么不走数值回读那条更"硬"的路**：skia 的 `ImageFilter.makeBlur` 数值探针量的是**原生库会不会算高斯**，
而这里要答的是 **Compose 桌面这一侧画不画**（`Modifier.blur` 是 graphicsLayer 上的 RenderEffect）。
拿前者的"能"去答后者的"画不画"，就又是一次错引读数。棋盘这种最高空间频率的图样本身就是量具 —— 糊没糊没有中间态。

## 3. 读数：画得出来

一帧 WGC 逐窗捕获（`occlusionSafe=true`，本机当时**锁屏**也拍得到 —— 这正是批 61 用的那条路）：

- 左边那枚：格边锐利，黑白分明；
- 右边那枚：**格边消失、整片糊成灰**，边缘还带出模糊的过渡带。

⇒ **应用内模糊在 Compose Desktop 1.12 上真画得出来**。stdout 那行 `S07B_窗口 已开 pid=23048 半径=24dp 棋盘=8x8 左=不糊 右=糊`
与帧里标题 `Venera 模糊渲染探针 #23048` 对上，帧归属核过。

别拿这一帧当它成立。
