## 1. 补的是什么

启动时多一行：

```
D_能力 剪贴板=有通路 词典=79415行
```

两件事从前只有屏上那一种读法：剪贴板拿不到时「复制图片」不摆（批 54）、词典没进包时译名静默走原文（批 40 那一族的前科）。
**两种在日志里都是一个字都没有**，事后翻不动。词典那枚尤其：打包改一行就会静默退回原文展示，而 743 颗判据全绿。

三态不压两态：`N行` / `包里没有`（枚举成功而清单空）/ `数不出（型=…）`（枚举本身抛了）。
「没取到 / 没有 / 没接」是三句话那条 —— 把"包残缺"念成"今天没查到词"就是一次误导。

## 2. 本批最重要的一条：新读数落地第一件事就推翻了自己第一版的措辞

第一版那句念的是 `剪贴板=可写`，而**同一台机器上批 54 量过真写被 OS 拒八次**（手册 坑 ㊛）。
活体一拍抓到两句并排：

```
D_能力 剪贴板=有通路 词典=79415行
D_复制图片 未成 因=CLIPBOARD_UNAVAILABLE 型=IllegalStateException 消息=cannot open system clipboard 栈=WClipboard.java:-2
```

⇒ `GraphicsEnvironment.isHeadless()` 说的是**那条 API 在不在**，不是"写一定成"。措辞退到量到的那一层
（有通路 / 无通路（headless）），真到写那一跳失败时出声的仍是批 54 那颗 `desktopCopyImageRefusalReading`：
**一枚念通路、一枚念结果，两句不许互相替**。判据 ② 现在钉的是"这句里不许出现「可写」"。
