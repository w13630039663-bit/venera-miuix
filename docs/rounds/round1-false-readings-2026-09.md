# 第 1 轮：屏幕上正在说错话的东西（2026-09-28）

来源是那次「对照 Breadboard 全面核查」的结论第一层。核查本身记在会话里，本文只记**这一轮改了什么、
怎么验、以及哪些是刻意没做的**。排序理由很简单：本仓的既有口径是"降级不许静默、按钮不能是假的、
读数必须等于真发出去的那份"，而这五条每天都在违反 —— 一个错的数字比少一个功能更伤信任。

## 一、双页模式「下一页」永远不动（`2873dda`）

`currentPageIndex` 在 DOUBLE_PAGE 下是组首（`doublePagerState.currentPage * 2`，恒为偶数），
而 `turnToNextPage` 写死 `+1`，那个奇数到了 `scrollToPage` 又被 `/2` 收回同一组。
连带页码气泡、进度条、自动巡航、进度持久化一起冻在偶数页上 —— 自动巡航尤其坏：
它在空转，却按"翻到了下一页"的语义在跑。

步长收进 `readerPageStep`，目标先**对齐组首**再跨步（交奇数页等于把纠正推给整除，
页码会短暂与实际摆出的组差一页）。到头/退无可退一律返回 `null` 而不是原页 ——
返回原页就是"按了没反应却算成功"。

单测 `ReaderInteractionPolicyTest` 加 6 例，其中一条钉的是序列本身：40 页连点必须走
`0,2,4…38` 然后报到头，不许回环。

## 二、每张 Gelbooru 图都写着「0 MB」（`0d957c1`）

`GalleryInfoSheet` 那行体积是无条件打印的，而 Gelbooru 的 post JSON 根本没有 `file_size`
（`GelbooruClient.kt:62` 记着这条天花板，也写了"UI 那边没这个读数就不显示"），解析处只能填 0。
同模块的 `GalleryVideoViewer` 早按"没有就不摆"修过同一处判据 —— 这是漏网的第二份。
第二层错法：整数除法把 yande.re 上不到 1.5 MB 的真文件也压成「0 MB」，所以有值也改走一位小数。

## 三、JPEG 书导入报成功、书架上却没有（`1b1b791`）

"什么算一页图"这个判据原本在**四处各抄一份**（`LocalComicManager` 两处扫描、
`DownloadManager` 的"下完了没"与"读离线页"），而**导入侧那份多收一个 `.jpeg`**。
不一致的后果是确定性的：导入成功、写成 `0001.jpeg`、扫描侧不认 → 书架上没有这本书，全程不报错。

收成 `download/PageImageFiles.kt` 一处，四路共用；导入把 `jpeg` 归一成 `jpg`
（文件名参与按名排序的页序，同一本书混两种后缀是隐患）。
**刻意没加 `gif`/`jpe`**：导入侧也不收它们，加了只是把"扩展名不一致"换成"两边都丢页"。

## 四、下一半的章被当成完整离线章（`357fc54`）

`chapter.json` 在**开下载之前**就写，而完成判据是"目录里有图" —— 于是"下到 5/40 被取消"
与"下完 40/40"在磁盘上长得一模一样。三处消费点一起把截断的书当完整书：详情页挂绿色「已下载」、
批量下载把它从默认选中里排除、阅读器拿本地文件当整章读（在线那一路不走了）。
挂着"已下载"意味着**永远不会被重下**。

现在元数据带 `expectedPages`（页列表取到后补写）与 `complete`（下完时写），
判据收成纯函数 `chapterOfflineState`。`PARTIAL` 的章不再交给阅读器当整章用（退回在线取全页：
宁可慢，不要静默少页），徽章分两档：绿色「已下载」/ 黄色「离线不全」。

⚠️ **迁移判据是这条改动的全部难点**：两个标记都没有的老数据必须**保持今日语义**。
否则设备上所有现存离线章一夜之间变"未下载" —— 那是用一个 bug 换一个更响的 bug
（同一类坑在 `relocateTasks` 的注释里有记录）。

## 五、过盾 cookie 的取证探针（`06b187b`，只读）

`onBypassSuccess` 里那句 `"... (includes cf_clearance)"` 是**无条件**打的，
它断言了一件没人验过的事 —— 而 `cf_clearance` 是 HttpOnly，`CookieManager.getCookie()` 按规范取不到。
两者必有一个是假的：要么日志一直假，要么"过盾成功"之后请求照样 403。
现在的证据只有"反搜那面墙从来没见过结果"，指不出断在哪一环。

这一笔不改任何判定，只记三样：实际取到的 **cookie 名字清单**（只记名字，值里含会话凭据）、
`cf_clearance` 在不在、过盾后那一笔重试的 **HTTP code**（两档都记 —— 只记失败就没法证明"曾经通过过"）。
`getCookie` 整串为空也单独一档：那是 WebView 与 OkHttp 两套存储根本没通，与"通着但 HttpOnly 取不到"
是两条不同病因。本机应用层 logcat 读不到，所以同时落文件：

```
adb exec-out run-as com.github.w13630039663bit.venera.miuix cat files/cf_bypass_evidence.txt
```

**拿到数之后这一层应整体撤掉**（它单独成文件就是为了好撤）。
真凶确认后要改的是 `Cookie.Builder().domain(host).path("/")` 那三处丢失（Secure/path/作用域）。

## 六、验证

- `testDebugUnitTest` **281 例全绿**（本轮新增 16 例 = 翻页步长 6 + 页图判据 5 + 章节完成 5，
  基线 265 例一条没退）、`assembleDebug` ✅。
- ⚠️ 这只证明纯函数判据与编译，**不证明屏上是对的样子**。真机判据（每条一步可做完，页面由用户点）：
  1. 双页模式点右下 → 页码气泡走 `1/40 → 3/40 → 5/40`，自动巡航真的在推进；
  2. 打开任意 Gelbooru 大图的信息面板 → 不再出现「0 MB」，yande.re 上小于 1.5 MB 的显示一位小数；
  3. 导入一本纯 JPEG 的 CBZ → 书架出现、页数对得上；
  4. 下载一章到一半取消 → 徽章是黄色「离线不全」而不是绿色「已下载」，批量下载默认选中它，
     点开它走在线而不是只读到前缀；
  5. 老数据回归：本轮之前下完的章，徽章仍是「已下载」，**没有**变成要重下；
  6. 撞一次盾 → 读 `cf_bypass_evidence.txt`，看 `cf_clearance=` 与 `post-bypass-retry code=`。
