# 批 77 · 上半 —— 画廊收藏那一屏的「清空」，而且是两步（2026-10-09）

## 这一格是什么

`GalleryFavorites` 的三枚写动作 `toggle` / `removeAll` / `clear` 全在共享面上，桌面那份
`DesktopGalleryFavorites.kt:24-25` 也逐枚转交了，而屏上只接了 `toggle` —— 那一屏的类注释本来就写着
"本屏没有移除/清空按钮"。**收藏多了清不掉**，而那份档是用户一张张攒起来的、不可重建。

盘点里那一格与批 76 同族（件在、只差接），但它多一层要求：**永久删除必须有确认**。

## 为什么是"同一屏上两步"而不是弹层

桌面今天没有 `ContentDialogHost`（全仓只有 `SpikeWindow` 那枚探针用过 `FluentDialog`）。为这一格去应用根
新铺一层宿主，是把"清空"和"引入弹层框架"两件事捆成一件。本仓已有的两处现成形状各说一件事：
设置那一屏删屏蔽规则**明写"没有确认那一步"**（代价低、敲回来一遍就行），搜索历史那枚「清空」直接可点
（只是历史）。收藏不属于那两类 ⇒ 这一格自持"武装 → 再按才真清"，而这两步都做成**纯函数**：
"第二按才是真清"这条纪律不该靠人眼点界面来确认。

## 改了什么

| 件 | 动作 |
|---|---|
| `gallery/ui/DesktopGalleryFavoritesClear.kt`（新） | `DesktopFavoritesClearStage`（`IDLE`/`ARMED`/`FIRE`）+ 三枚纯函数（`…Label` / `…Next` / `…Visible`）+ `DesktopClearOutcome`（`Cleared(cleared,left)` / `Failed(reason,error)`）+ 那颗 suspend 写口（IO 上跑，清完**读回**收藏流还剩几条，两行 stdout） |
| `gallery/ui/DesktopGalleryFavoritesPane.kt` | 段头下面那一排：`清空全部 N 条` → 按一次变 `确认清空这 N 条？…` + 一枚「先不清了」；结果那一句摆上屏（失败红字）；`armedAt` 存的是**条数**不是 bool |

三条设计要点，各有一颗尺子：

1. **两档各念一句且都点名条数** —— 不念条数的确认等于"确认一个未知量"。
2. **条数变了就重新武装** —— 武装着去别处翻了一页、或别的进程往档里加了条目，再按下去删的就不是屏上那批。
3. **清完读回还剩几条** —— 共享面的 `clear()` 返回 `Unit`，"清没清干净"只有读回知道；
   读回非 0 而那句念"已清空"，就是把没生效说成生效。那一句现在长成：
   `按下去说清了 3 条，而存档里还剩 3 条 —— 这一屏别信，去数据目录看一眼`。

屏上那一句会不会跟着变没有。挂 §17 第 2 项第 ⑥ 枚。

## 尺子：10 条，七笔扰动各咬各的

`DesktopGalleryFavoritesClearTest`（10 条）＋ `_qa/b77_perturb.js`（`sh _qa/perturb_driver.sh b77 7`）：

| 假动作 | 红了哪条 |
|---|---|
| P1 `countNow == countAtArm` → `<=`（少几条也算数） | ② |
| P2 两档撞成同一句 | ① |
| P3 `left == 0` → `left >= 0`（读回非零也说已清空） | ⑤ |
| P4 成功那行不打印 | ⑦ ＋ 零调用点那把（`…RefusalReading` 成了仅测试引用） |
| P5 屏上绕过那颗件直接 `ports.favorites.clear()` | ④  零调用点那把 |
| P6 「先不清了」那枚撤掉 | ④ 的复位计数（两处 → 一处） |
| P7 `runCatching { favorites.clear() }` → `runCatching { }`（按下去而没真清） | ⑧ ＋ **⑩（真档那条）** |

P7 是这批最值的一笔：它让"形状全对而什么都没清"这种最像真的假动作在**真盘**上红 ——
⑩ 的失败消息直接念出 `按下去说清了 3 条，而存档里还剩 3 条`。

## 两处自己踩的坑（都补了尺子或记进注释）

- **⑨ 的对照写瞎了一次**：拿"两步""武装"这种词去 `codeText` 里找对照，而 `codeText` **跳注释**
  ⇒ 那条恒假、整颗判据第一次跑就红在自己的对照上。改成吃代码里的形状
  （`desktopFavoritesClearNext(` + `DesktopFavoritesClearStage.ARMED`）。
  这是"判式把证据送到它看不见的地方"那一族的又一形态：**说明里的话不能当行为凭据**。
- **⑩ 单跑绿、全量红**：`GalleryFavoritesStore.getInstance` 是进程级单例，整棵跑时
  `SharedStoreAtomicWriteTest` 先按它自己的临时目录建好了 ⇒ 我这里写的是**别人的档**，
  而我去读自己那个不存在的文件。改成自建 `GalleryFavoritesStore(paths)`（那颗构造器是 `internal`，
  桌面这一侧够得着）。⚠️ 同一族记忆早就在账上（"接一族前先量两份存储"），这次是它换了个方向咬人：
  **测试吃单例 = 用例之间互相决定成败**。
