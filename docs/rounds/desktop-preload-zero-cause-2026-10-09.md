## 1. 补的是什么

批 56 让预取念两行，但 `排=0` 只说"这一轮一笔都不发"。而**四种缺席在屏上同形**：

| 因 | 那一句 |
| --- | --- |
| 档设成了不预取（`OFF`） | `（这一轮一笔都不发：档设成了不预取）` |
| 前后没有那几张了（翻到底 / 墙是空的） | `（这一轮一笔都不发：前后没有那几张了）` |
| 前后那几张被分级挡住 | `（这一轮一笔都不发：挡=1）` |
| 站方没给可取的地址（视频没封面算这一枚） | `（这一轮一笔都不发：无址=1）` |

后两种可以同时成立 ⇒ 两枚计数都念（`挡=1 无址=1`）。这正是「没取到 / 没有 / 没接」那一族：
少说一种因，就会有人拿"它坏了"去查一条本来按设计没动的路。

## 2. 形状：账本与计划同一颗件、同一次过滤

`desktopPreloadUrls(...): List<String>` 换成 `desktopPreloadPlan(...): DesktopPreloadPlan`，
四枚计数（`urls / wanted / blocked / noUrl`）就在原来那三道 filter 的**同一次**走里顺手数出来。
刻意不做的事：不给 `desktopPreloadUrls` 留一颗"只回地址表"的旧壳 —— 那样集成方要用两颗、
或让旧壳变成零调用点（批 26 那一族），两条都比改 9 处测试贵。
次序是判式的一部分：**先认 `OFF` 再认 `wanted == 0`** —— 不预取那一档同样算出 `wanted=0`，反了就把"人关掉了"报成"翻到底了"。
