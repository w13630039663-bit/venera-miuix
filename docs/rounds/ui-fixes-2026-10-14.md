## 无人值守期间的决策（负责人不在，按推荐做法做并记在这里）

| # | 抉择点 | 取定 | 理由 |
|---|---|---|---|
| D1 | 平板/宽屏档 | 本轮**不改** | 明说"模拟器不能旋转，只看手机版本"；宽屏"内容不限宽"另开一轮 |
| D2 | 下载并发的假说法 | **改实现**（队列循环每轮现取偏好值），不是改文案 | 只改文案是把假话改小 |
| D3 | 追更整页零入口 | **补设置入口**（设置 → 应用 一行 + 路由） | 数据层与排程都在，只差那一跳；删整页是浪费 |
| D4 | 「画成水彩 Beta」的权重 | 从**独占整行**降为动作条最下那一档小字入口 | 实验件不该拿最高视觉权重 |
| D4′ | 降级的落点 | **不**放进节头右侧，而是留在动作条、降为最低权重那一档 | 节头右侧那个位置在本仓的语义是"展开/收起**这一块**"（`SheetSectionHeader.onAction` 的既有口径），挂一个跨块动作会被读成"展开基本信息" |
| D5 | 面板里的彩色徽标 | 块标题徽标**去色**（中性），一屏只留分级那一枚彩色锚点 | 6+ 种高饱和色没有锚点 |
| D6 | 令牌存量（130 sp / 27 Color / 630 dp） | 冻结成**白名单尺子，只许缩短**；不做大迁移 | 一次性迁移 = 大重构，回归风险远大于收益 |
| D7 | 两套底栏合一 | 只修硬编码浅色底，不抽公共基座 | 抽基座要同时动玻璃档，手机档截图验不到差异 |
| D8 | 提交节奏 | 每批一次 commit，**不 push**；最后统一问是否 push 与是否再出包 | push 需明确授权 |

## 批 2 · 画廊内容区的提示只许一行（P0）

**立案读数（改前）**：手机档画廊首页，两块提示各占 3~4 行正文（标题 + "为什么 + 去哪儿配 + 另一站不受影响"），
把「正在关注的画师 / 每日热门」整块推出首屏 —— 核心模块的第一眼成了故障说明书。

**改法**：`VeneraNotice` 加 `compact`（一行档）。

- `components/venera/VeneraNotice.kt`：`compact` 时那一行只摆「图标 + 标题（**单行**，超长省略）+ 出口胶囊 + 展开把手」，
  正文改成**点这一行就地展开**；`collapsible = compact && hasTitle && message.isNotBlank()` 同时决定把手与整行的可点性 ——
  没有正文可展开时既不摆箭头也不挂点击（假开关）。`onClickLabel` 给读屏念"展开说明/收起说明"。
- `gallery/ui/GalleryNotices.kt`：`compact` 是**必填形参、无默认值**（第四个调用点必须当场决定一次，不许靠默认值长成多行块）。
- 三面墙（首页 `GalleryScreen` / 按收藏推荐 `GalleryForYouScreen` / 搜索 `GallerySearchArea`）全部递 `compact = true`。
- 措辞一个字没删：`noticeTitle` 从 private 退成 internal，为的是让"标题是不是单行短句"能被**行为**测到。

**判据**：`UiAuditBatch2Test` 6 条（4 条扫源码 + 2 条测 `noticeTitle` 行为，含两站并起那一档）。
扰动 6 笔全部咬住（`_qa/ui-audit-2026-10-14/after/perturb-b2.log`：`RED B2-P1..P6`，`not_biting=0`）。
其中 P4 那笔的 `restored=false` 是**量具自己的假阴** —— 终点串是起点串的前缀，`!includes(to)` 恒假；源码已回读确认还原。

**真机改后读数**（`after/b2-02-gallery-home.png` + `after/dump-2.xml`）：
两块提示各占一行；「正在关注的画师」标题落在 y=1219、「每日热门」y=1816（屏高 2560）—— **两节都回到首屏内**。
点那一行后（`after/dump-3.xml`）正文整段上屏（"它的接口对匿名请求一律拒绝（401）…填 User ID 与 API Key…"，y=1009-1183）。

## 复核后**撤销**的两条（不照报告改，理由在此）

1. **「分级同时出现在顶部徽标与基本信息里」不成立。** 面板里只有标题行那一枚分级徽标；
   ① 事实网格那一格是 `post.score`（**评分**，一个数字），与 `post.rating`（分级）是两个字段。
   报告把截图上的「评分 20」读成了分级。⇒ 不删任何一格。
2. **「长标签撑破版面」已经按报告给的另一种解法落地。** `GalleryTagChip` 现写 `textMaxLines = 2`
   （`GalleryInfoSheet.kt:1256`，注释就记着"单行省略后既读不到全词也复制不到全词"），
   而 `FlowRow` 的约束本身会封顶宽度。⇒ 不再另加 `maxWidth`（那是同一件事的第三套写法）。

## 批 4 · 横向溢出的证据 + 探索页的光杆标题（P1）

**新增基础件** `components/venera/VeneraHScrollFade.kt`：`hScrollEndFade(container)` +
`hScrollEndContentPadding()` —— 右缘渐隐（"还有东西在屏幕外"第一次有了视觉证据）与
**尾部内容内边距**（滑到底时末枚要整个退出渐隐区）。两半必须成对：只接一半等于把"被裁"
从中途挪到终点。`container` **必填无默认值**（页面底与卡面不是一种颜色）。
接上三处：搜索页「漫画源」药丸行、收藏页文件夹行、详情页分组 tabs。

**探索页**（真机第一遍截图 `after/b4-02-explore.png` 量到四行标题、下面几乎全空）：
- 零入口的分类组在**源头**剔掉（`allSections` 上 `filter { it.items.isNotEmpty() }`）——
  屏上那两行光杆「Tags」「内容」就是这么来的；折叠计数与预算两本账一起对上；
- 榜档同一判据；「本源分类」那枚节头改判"非空"而不是"存在"；
- 「内容」节头跟着内容走（加载中 / 失败 / 空 三档下面各自会念一句话）；
- 上方那枚「快捷筛选」总标题**整枚撤掉**：它管的两块各自带题，套层就是两行标题压一行药丸。

**搜索页**那句两行技术解释改走 `VeneraNotice` 的一行档（批 2 那颗件），措辞一个字没删。

**判据**：`UiAuditBatch4Test` 5 条；扰动 5 笔全咬住（`perturb-b4.log`，`fresh=true` 逐笔记了 mtime 门）。
两处量具自己的坑记在此：① 第一遍 `rm -f` 的路径带反斜杠被 bash 吃掉 ⇒ 旧 XML 会被当读数；
② 跨行锚点在 CRLF 文件里必须写 `\r\n`（`compact = true,` 那一笔因此先误报"锚点 2 处"）。

**本轮没做的一条（记录理由）**：报告里"整页空态垂直居中"三处。三处空态都坐在 lazy item 里，
`fillMaxSize` 在无界高度下是整屏崩那一族（本仓有判据），要真居中就得把空态连同文件夹行、
搜索行一起从列表里提出来 —— 那是结构改动而不是观感改动，留作下一轮。
画廊首页那三行 `Row + horizontalScroll` 也**没**接渐隐：它们右边自带「另有 N 位」这种
显式说法，而 `Row` 没有 `contentPadding` 这一档，只接渐隐就成了上面说的"半修"。

## 批 7 · 回读时抓到的一条漏网 P1（网络收藏的源药丸行）

收尾清点报告逐条下落时发现：**报告 2.3 那条 P1「源药丸行被裁成 `● nl`」批 4 其实没关掉**。
