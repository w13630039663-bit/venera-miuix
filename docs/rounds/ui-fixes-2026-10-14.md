|---|---|---|---|

| D4 | 「画成水彩 Beta」的权重 | 从**独占整行**降为动作条最下那一档小字入口 | 实验件不该拿最高视觉权重 |

| D5 | 面板里的彩色徽标 | 块标题徽标**去色**（中性），一屏只留分级那一枚彩色锚点 | 6+ 种高饱和色没有锚点 |

## 批 2 · 画廊内容区的提示只许一行（P0）

**立案读数（改前）**：手机档画廊首页，两块提示各占 3~4 行正文（标题 + "为什么 + 去哪儿配 + 另一站不受影响"），
把「正在关注的画师 / 每日热门」整块推出首屏 —— 核心模块的第一眼成了故障说明书。

**改法**：`VeneraNotice` 加 `compact`（一行档）。

- `components/venera/VeneraNotice.kt`：`compact` 时那一行只摆「图标 + 标题（**单行**，超长省略）+ 出口胶囊 + 展开把手」，
  正文改成**点这一行就地展开**；`collapsible = compact && hasTitle && message.isNotBlank()` 同时决定把手与整行的可点性 ——
  没有正文可展开时既不摆箭头也不挂点击（假开关）。`onClickLabel` 给读屏念"展开说明/收起说明"。
- `gallery/ui/GalleryNotices.kt`：`compact` 是**必填形参、无默认值**（第四个调用点必须当场决定一次，不许靠默认值长成多行块）。
- 三面墙（首页 `GalleryScreen` / 按收藏推荐 `GalleryForYouScreen` / 搜索 `GallerySearchArea`）全部递 `compact = true`。
- 措辞一个字没删：`noticeTitle` 从 private 退成 internal，为的是让"标题是不是单行短句"能被**行为**测到。

**判据**：`UiAuditBatch2Test` 6 条（4 条扫源码 + 2 条测 `noticeTitle` 行为，含两站并起那一档）。
扰动 6 笔全部咬住（`_qa/ui-audit-2026-10-14/after/perturb-b2.log`：`RED B2-P1..P6`，`not_biting=0`）。
其中 P4 那笔的 `restored=false` 是**量具自己的假阴** —— 终点串是起点串的前缀，`!includes(to)` 恒假；源码已回读确认还原。

**真机改后读数**（`after/b2-02-gallery-home.png` + `after/dump-2.xml`）：
两块提示各占一行；「正在关注的画师」标题落在 y=1219、「每日热门」y=1816（屏高 2560）—— **两节都回到首屏内**。
点那一行后（`after/dump-3.xml`）正文整段上屏（"它的接口对匿名请求一律拒绝（401）…填 User ID 与 API Key…"，y=1009-1183）。

## 复核后**撤销**的两条（不照报告改，理由在此）

1. **「分级同时出现在顶部徽标与基本信息里」不成立。** 面板里只有标题行那一枚分级徽标；
   ① 事实网格那一格是 `post.score`（**评分**，一个数字），与 `post.rating`（分级）是两个字段。
   报告把截图上的「评分 20」读成了分级。⇒ 不删任何一格。
2. **「长标签撑破版面」已经按报告给的另一种解法落地。** `GalleryTagChip` 现写 `textMaxLines = 2`
   （`GalleryInfoSheet.kt:1256`，注释就记着"单行省略后既读不到全词也复制不到全词"），
   而 `FlowRow` 的约束本身会封顶宽度。⇒ 不再另加 `maxWidth`（那是同一件事的第三套写法）。
