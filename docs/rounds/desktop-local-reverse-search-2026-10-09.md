# 桌面批 77 · 下半 · 「用本机的一张图找同一张」那一格（2026-10-09）

## 这批补的是哪一格

批 35 把 `searchByFile` 从抛桩换成真转交，而它自己的类注释写着实话：**接上了而界面上还差走到这里的那一步**
（差的是"用户从本机挑一张图"）。本批把那一步做出来，于是桌面这一族的两路输入齐了：

| 输入 | 屏上入口 | 发出去的调用 |
|---|---|---|
| 站方那一张的地址 | 详情浮层「找同一张图」（批 35） | `searchByUrl` |
| 本机的一张图 | 搜索那一屏「用本机的一张图找」（本批） | `searchByFile` |

对岸的入口位置逐字照做：`GallerySearchArea` 把反搜那颗挂在**搜索卡输入行的尾随格**，
所以桌面这一枚跟在输入行之后，而不是另起一屏。

## 三条设计上的取舍，各有一条尺子

1. **落点不新造**：`desktopLocalReverseRun` 交回的是批 35 那颗 `DesktopReverseOutcome`
   （没发车 / 摆得出 / 站方说没有 / 没搜成），四档句子全部转交 `DesktopReverseSearchPolicy`。
   判据 ⑩ 不做"你看我调了那颗件"这种断言，而是**数那两句字面量在全树出现几次**（各 1 次）——
   抄一份句子时字面量会变两处，那种红才是能拦事的红。
2. **输入端那颗闸是新造的，且是六档**：没挑 / 没键 / 找不到 / 是目录 / 认不出图 / 0 字节 / 超上限
   （"没键"那一档复用 [DESKTOP_REVERSE_NO_KEY_REASON]，见下面第三条）。
   后四档是**桌面才有的**：Android 由 ContentResolver 代挑，不存在"路径指向一个目录"这种东西。
   次序就是判据，与对岸 `submit()` 一致：没挑时不去问键（那句会把注意力带去配一枚用不上的键），
   没键时不去读那张文件（根本没发车）。判据 ①③ 各钉一格，其中①是"两档同时成立时念哪句"那种单独一格。
3. **上限那枚数不许漂**：`6L * 1024 * 1024` 与对岸 `GalleryReverseViewModel.MAX_UPLOAD_BYTES` 同值，
   判据 ④ **回读对岸那颗文件**（`DesktopSourceTree.androidSource(...)`）而不是信桌面这边的一句注释。
   ⚠️ 有意的一处不同：那句人话这里**往上取整**，对岸往下取整会把 6,291,457 字节念成
   「这张图 6 MB，超过 6 MB 不发」—— 一句自相矛盾的话。差异写在类注释里而不是悄悄改。

## 一处今天拿不到的读数，不写成拿到了

**系统文件框那一步没有像素读数**：鼠标自验是禁的（手册 §8），模态框只能人手点。
`--reverse-file=` 走的是"**跳过**文件框、直接给一条路径"，它验到的是路径之后的三跳。
所以本批文档、类注释、判据 ⑰ 三处都写着同一句：那枚按钮"按下真能弹出一个能选的框"这一条
**只有代码在场这一种证据**。这也是它与批 36 `--reverse` 的实差（那枚是"自动按一次屏上已有的按钮"）。

同一族的另一处：`readFile` 与 `onThrowable` 两枚回调参数**必填、不给默认值**
（`DesktopCallbackParamLedgerTest` 那条禁令抓到本批第一次写法就红了一次）。
`onThrowable` 存在的理由是"失败那第二行读数要的是异常类型与栈顶帧"，
从被压成字符串的落点里猜不出那两枚 ⇒ 判据 ⑬ 钉的是它必须递**真异常**而不是 `null`。

## 图证抓到本批自己的一枚错（读数与行为不一致）

帧 A 的 stdout 第一版念的是 `挑=没挑`，而用户明明递了一条路径 —— 因为那颗读数从**闸口**取文件名，
而挡住那一档的闸口里没有文件名。屏上那句是对的（「先去填一枚免费 key…」），只有日志那一眼看得见错。
改法：`desktopLocalReverseReadout` 多收一枚 `path`（必填），挡住时从路径现取文件名，
只有真没挑才念「没挑」；判据 ⑫ 加两条（给了路径而挡住 ⇒ 念得出是哪一张；真没挑 ⇒ 才念没挑）。
这是本仓那条"读数与行为不一致时只有图证抓得到"的**第四次**应用。

## 两处工具坑（也记在这里）

- 包那一层第一次 `sync_pkg` 把源目录指到了 `…/binaries/main/app`（它下面是**子目录** `venera-desktop-probe`），
  于是 105 件全被"移"进 `_qa/_trash_b77b`。`sync_pkg.js` 是**移不是删**，改对源之后全数回来，复跑 `check_cfg` = missing 0 / orphan 0。
  教训：那一颗脚本只认"目录里的文件"，指错一层不会报错，只会把上一版搬空。
- PowerShell 起包时 `[Console]::OutputEncoding` 默认按 GBK 解 java 的 UTF-8 ⇒ 日志里整片 U+FFFD（读数存在而读不出）。
  包装脚本里显式设成 UTF-8 之后 `D_反搜本地` 那几行才念得出来。
