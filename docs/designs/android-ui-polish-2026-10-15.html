Android 观感美化方案

依据：_qa/ui-verify-2026-10-15 全套真机截图（1080×2376，124 张）＋ 主分支代码通读

范围：只谈 app/ 手机档。未动一行代码，本文是方案稿。

一句话结论：结构层已经成熟，短板全在「视觉重量分配」。

令牌体系、玻璃三档、氛围光背景、空态组件、动效令牌都已经收口，公共件也基本只有单一入口。 真正让屏与屏读起来不像同一个 app 的，不是散抄的 dp，而是每一屏里「谁重谁轻」没有设计—— 三个等权的统计数字、五个色身份打架的动作钮、六枚一样重的阅读器按钮、一行没有标签的裸图标。 这些都不需要新架构，只需要重新分配已有的层级。

一、五处按「一眼能看见」排序的修改

① 空态：一枚灰图标 + 两行字 + 六成空白

受影响 5 屏以上：收藏（网络/图片/本地三档）、搜索、探索、追更、下载队列。 现在空态是 32dp 的 textDisabled 图标配两行居中文字，往下什么都没有。

屏上最难看的不是它小，而是没有承重物：上半屏挤着大标题、分段器、源药丸三层控件， 下半屏整片空，视线落不到任何地方。而 VeneraEmptyView 已经有 Nothing / NotYet / Failed 三档语义和 Regular / Compact / Inline 三档尺寸， 缺的只是「Regular 档该长什么样」这件事从来没被设计过。

空态：现状 vs 建议

做法：把 Regular 档拆成四层——氛围层（主题色径向柔光，两枚同心圆即可，不引渐变资源）、 图形层（线稿字形，不是 emoji 也不是位图）、文案层（标题 + 说明）、行动层（主按钮 + 一条次级文字链接）。 这跟已有的 VeneraAmbientBackground 是同一套语言，深浅档与任意种子色都成立。

  • 色彩全部走 tokens.color.primary / outlineVariant / textSecondary，不新增 token。
  • 图形层用 Canvas 画，不引 drawable 资源，任意种子色自动适配。
  • 唯一新增能力是「行动层」：现在 VeneraEmptyView 已有 actionText / onAction 两个参数， 但 65 处调用里几乎没有一屏真的传了——这是最便宜的一处改动。

② 首页「阅读统计」卡：三个等权数字，没有形状

57 / 151 / 2 三格平分卡宽、中间两条发丝线。三个数字一样大、一样重， 但「今天读了多少」和「连续几天」对一个阅读 app 的意义完全不同，屏上却是同一档。

首页阅读统计卡：现状 vs 建议

做法：一个主数字（今日）+ 一条近 7 天迷你柱（今天吃主题色，其余吃 surfaceVariant）+ 底部一行两个副指标（本周 / 连续）。 数据全部现成——HomeViewModel 已有 todayPages / weekPages / streakDays， StatsScreen 已有 14 天趋势，「比昨天多 N 页」是两次减法。

这一处会动 HomeScreen.kt，而它在第四批冻结名单里。 按 FREEZE-STATEMENT.md 的口径，属「视觉重构」需走豁免评审； 建议与 ③④⑤ 一起打包成一次「观感批次」，一次评审、一次真机成对截图。

③ 详情页动作行：五个动作的色身份是坏的

这是逐像素核出来的：五枚圆座里，收藏 / 点赞是同一支粉、评论是琥珀、分享与复制链接几乎没有底色， 后两枚在屏上读起来像禁用态。而 Color.kt 里登记的语义映射是 favorite 紫 / like 粉 / comment 绿 / share 蓝——屏上跟文档对不上，说明这一行是绕过 token 手写死的。

详情页动作行：现状 vs 建议

做法：不要「五个动作五个颜色」，那本身就是错的方向。按语义分两族：

  • 状态型（收藏 / 点赞）——它们记录「我做过什么」。已做 = 主题色实底 + onPrimary 字形； 未做 = 中性底 + 描边。屏上因此只有「我做过的那件事」是亮的。
  • 动作型（评论 / 分享 / 复制链接）——它们没有状态，统一中性底 + textSecondary 字形。
  • 顺带合并：复制链接本就是分享面板里的一项，五个动作收敛成四个，那一行立刻松下来。

④ 阅读器底栏：柄高是轨道的四倍，25 个点读成噪点

页码条上画了 25 枚粉点，而拖动柄是一根比轨道高四倍的竖条——两者不是一套语言。 下面六枚按钮等大等重，但「目录 / 设置」是每话都要用的，「存图 / 插图 / 分享」一话未必碰一次。

阅读器底栏：现状 vs 建议

做法：

  • 页码条改成实心进度 + 同高圆柄（柄直径与轨道等高），页点只在 ≤12 页 时保留—— 25 页已经是噪点，200 页会连成一条实线。
  • 按钮分两档：目录 / 设置 / 亮度 三枚带字主按钮，其余收进「更多」。 或者更省的改法——保留六枚但去掉次级四枚的标签、缩一档，让主次在尺寸上就分得开。
  • 章节名上移进顶栏（现在顶栏是「截断标题 + 第X话」两段，底栏又重复一次「1/25」）。
  • 设置面板是玻璃叠在漫画页上，对比度明显不足——面板需要更实的底（提高容器 alpha 或换 surfaceContainerHigh），这一条与 VeneraGlass 头注里「玻璃提亮量 = alpha ×(容器色 − 底色)」的推导同源。

⑤ 图源管理：六枚无标签裸图标，删除键紧挨刷新键

展开一张源卡，控制区是 ★ ↑ ↓ ↻ ⟳ 🗑 六枚没有标签的图标排成一行。 这是全 app 最容易误触的一屏，也是最难读懂的一屏。

图源管理控制区：现状 vs 建议

做法：保留「启用开关」+「设为活跃★」两个高频控制（前者已经足够醒目）， 其余（上移 / 下移 / 刷新 / 检查更新 / 删除）进「更多」菜单， 并把注销与删除放进菜单底部独立的危险区——破坏性动作不与常规动作混排， 这是这一屏最实质的一处改善，不只是好看。

二、两处结构性的「看得见但没做」

卡片材质只覆盖了 3 处，23 颗裸 Card 拿不到玻璃

docs/rounds/ui-consistency-audit-2026-10-15.md 已经量过：接玻璃的只有 VeneraCard.kt:45、SettingsComponents.kt:82、GallerySheetBlock.kt:64， 而裸 miuix Card( 还有 23 处 / 14 文件。结果是液态玻璃档下整屏卡面没有玻璃响应—— 用户在设置里开了玻璃，只有零星几处变了。

这不是美化项，是一个已上线开关的兑现问题：要么把那 23 处收进 VeneraCard， 要么明确「玻璃只作用于这些层级」并写进设置项的说明文字。现状是两者都没做。

深色档下卡面与页底差得太小

截图里能看出：暗色主题下页面底是近黑，而卡面只亮了一点点，加上顶部氛围光把页面底提亮， 卡片边界全靠那圈发丝描边撑着。仓内纪律是「层次走填充差不补描边」， 所以正确的修法是把卡面那一档槽位往 surfaceContainerHigh 靠， 而不是给卡片加描边——VeneraGlass 头注里量过同一件事： 「顶栏与搜索框实测亮 +27 / +23，因为它们走的是 surfaceContainerHigh」，同一个 alpha 在 chrome 有效、在内容区失效，该换的是槽位。

四、建议的批次与优先级

序做什么影响面代价冻结
1空态 Regular 档重设计（组件层一处改动，5+ 屏受益）5 屏以上小不碰冻结页
2详情页动作行：状态型/动作型分族 + 合并分享与复制链接详情页小未冻结
3图源管理控制区收口 + 破坏性动作隔离1 屏小未冻结
4阅读器底栏：实心进度 + 按钮分档1 屏小-中未冻结
5首页统计卡重排（主数字 + 7 天柱 + 副指标）首页小需豁免
6卡片材质收口（23 颗裸 Card → VeneraCard）14 文件中部分需豁免
7探索行标签墙限 2 行 + 「+N」探索页小已冻结

建议 1–4 合成一个批次先做：四处都不碰冻结页、都不新增 token、都能一次真机成对截图验收。 5 与 6 因为涉及冻结页与跨文件，单独走一次评审。

  • 动效与加载（容器变形转场、跟手返回统一、转场首帧不白板、预加载窗口优先级序） ——见 docs/rounds/reference-project-ui-plan-2026-10-15.md 的批 A/B/C。
