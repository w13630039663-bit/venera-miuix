因为你也读过这些

大胆的部位只有一处：hero 与阅读痕迹；网格被破的是节奏，不是列数公式

1hero 用不规则分格：大格斜切并出血压过侧栏 24（满幅档 48），字格被封面角遮住一角——这才是"穿插"，不是"叠了两张卡"。 2继续阅读首卡放大 1.35 倍并向上咬进 hero 14，后两张依次下移 18/30；非对称来自错位，不来自随机。 3统计条是旋转 −3° 的贴纸，横跨两区交界，是全页唯一浮在网格之上的数据件。 4推荐墙仍 5 列、每列 200 预算照本仓公式；破格只用"首格跨 2 列 16:10 + 交替左边距"表达。 5漫画语汇四件：分格硬描边（满幅档 3px）、网点底纹、速度线、贴纸标签（新番/续读/追更）。 6强调双色固定在品红 #FF5FA2 与青 #4DE1F1，只用于贴纸与 kicker；中性 surface 阶梯一分未动——这是"仍像 Windows 应用"的锚。

哪里允许破，哪里必须不破

部位判定理由
hero / 编辑位 / 装饰层可破：出血、斜切、旋转、重叠、竖排大字纯展示，不承载精确对齐，错了也只是难看
封面墙列数不可破：每列 200 预算与取整方向照本仓公式列数是"只许加不许减"的量，且直接决定卡片尺寸
侧栏导航不可破：40 高 / 224 宽 / 选中指示条键盘焦点顺序与读屏依赖它
正文与元信息不可破：不旋转、不上渐变字、行高不动旋转与描边会吃掉对比度，中文尤其明显
浮层（菜单 / Tooltip / 详情）不可破：实底、直角 4、无网点系统玻璃采不到独立窗口，装饰叠加只会更糊
状态栏 / 标题栏不可破：24 / 40 高，caption 46×32Windows 识别度来自这里，不是来自 hero

代价与待量

实现成本上移：分格描边、clip-path 斜切、旋转贴纸、竖排大字全在 compose-fluent 覆盖范围之外，只能自绘；满幅档比克制档多约 6 类私有部件。 渲染开销未量：桌面是 skiko 光栅，clip-path 与 mask 会触发离屏合成；网点与速度线若常驻底纹，滚动帧时间要实测，量不过就退克制档，不许默认开着。 必须能一键关：设置项「页面感装饰」三档，默认页面感；窗口宽 < 1280 强制回落克制档——出血与重叠在窄窗会互相压字。 与手机档分叉变大：分格与贴纸是桌面版式语言，Android 不跟；同源的仍只有列数公式、断点定义、种子色链路三件。 几何只校过一档：出血 24/48 与错位 14/18/30 目前只在 1440 校过，1280 与 1920 两档要各看一眼。渲染实测另有一条：满幅档 hero 高 470，推荐墙会整块掉到折叠以下，所以满幅只能当"展示档"，不能当默认档。 假名点缀只两处（kicker 与 furi），且随装饰开关一起关。

交付前检查单

装饰层 aria-hidden，读屏只念标题与元信息 正文对比度 ≥ 4.5:1（#E4E4E4 / #202020） 旋转只用于贴纸与卡片外框，文字不旋转 prefers-reduced-motion 已接 hover 不引起位移（动作条仍是封面覆盖条） 满幅档 hero 在 1280 宽会遮住继续阅读首卡，需自动降档 窄窗下贴纸的硬阴影会与相邻文字叠色
