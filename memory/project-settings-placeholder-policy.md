2026-09-19 设置树审计后与用户共同定下的判据：

**判据已于 2026-09-30 更新（用户拍板，以这条为准）**：设置页里"未实现/暂不支持"的灰行**连标题整条撤掉**，不再保留任何一条，也不折成底部折叠区；
配套件 `SettingsFutureGroup` 与 `UnsupportedSetting` 已因零调用点删除。缺口信息一律留在 `settings-audit-2026-09.md`，不拿设置页当 TODO。

旧判据（2026-09-19，已被上面取代，仅留档）：只保留"引擎已在、只差一个键"的那类，其余删行；该轮按此删掉 32 条（54 → 22 处调用点），
剩下的 12 条在 2026-09-30 全部撤完。见 [[feedback-ui-text-no-ai-flavor]]。

**已明确"主动不做"的项，别顺手实现**（都有具体理由，重新提出要先推翻这些理由）：

- **DoH / DNS 覆盖**：`DnsOverHttps` 虽已 import 但从未 `builder.dns()`；强制 DoH 在国内网络下可能整体不可达，属高风险网络变更，不是"差一个开关"。
- **检查更新 / 启动时检查更新**：这个 fork 没有自己的发布通道，用参考版版本号判断更新是错的；About 页已有「上游发布频道」链接。
- **长按缩放 + 长按缩放位置**：等"双击缩放"（telephoto 已在依赖里）做完看手感，现在两行灰行无意义。
- **沉浸式背景 / 自定义壁纸 / 模糊强度 / 返回动画样式**：壁纸与动画样式体系是独立工程，无排期。
- **语言切换、存储路径迁移（SAF）**：各自是一整块工程。
- **「在网络收藏前显示本地收藏」**：键与 setter 都在但**无任何消费者**（收藏面板顺序硬编码），属改不动也无效的假开关 —— 这类"僵尸开关"的处置是删行，不是留着显示已保存值。

**安全/凭据类要单独评审，不塞进顺手批次**：应用锁（androidx.biometric）、代理用户名密码（凭据不能进普通 SharedPreferences）、强制直连（要绕系统 ProxySelector）。

**撤掉一个偏好选项时的口径（2026-09-24 用户认可的处置）**：设置项的功能一旦消失，那一行/那个选项**必须撤掉**（留着就是假开关），
同时**存量值不静默改写**：
- 枚举类值要**从枚举里物理删除**，不是留着当死值 —— 留着 `valueOf(旧值)` 仍合法，旧存档会被悄悄当成"用户还要它"，成了一条没人会发现的死分支；
- 读取侧靠 `runCatching { valueOf() }.getOrDefault(默认)` 回落，并让设置那一行显示现成的「未识别的已保存值：X」；
- 一句话：**用户改过的偏好被动了要说得出来**，静默回落可以，静默吞掉不行。

**Why:** 用户明确选了"只删不做的那批"，且对"假开关 / 过度承诺文案"零容忍（同轮要求把"导出应用数据"改成如实的"导出阅读与收藏数据"）。

**How to apply:** 看到灰行先问"引擎是否已有"，有就实现、没有就删行并记进审计文档；不要为了"看起来功能齐全"保留或新增灰行。相关：[[venera-ui-refactor-authoritative-docs]]。
