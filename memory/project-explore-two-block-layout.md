2026-09-20 用户给出完整信息架构 spec（连说三遍、逐遍细化，最后定稿）：探索页内容区拆成上下两个区块。

- **上方「快捷筛选」**：探索方式（随机/最新/排行…）+ 真正跨源通用的标签。点击**不跳转**，直接刷新本页内容区，方便与探索方式组合筛选。实现走**本源 search 接口**，结果包成单个无标题分区喂进现有渲染管线（守卫打码、单双列、分页、共享元素 key 全复用）。再点同一标签=取消；切源或切探索方式自动清除筛选（否则两个数据来源同时生效，用户看不出列表哪来的）。**不吸顶**（用户选项，理由：与"大标题折叠 + 毛玻璃顶栏"共存最稳）。
- **下方「本源分类」**：源专属分类组 + 排行榜入口，点击跳二级列表页（行为不变）。默认按组顺序消耗 8 个入口的预算（`ExploreViewModel.SECTION_ENTRY_BUDGET`），超出的组收起，底部「更多分类（还有 N 个）」/「收起分类」。

**两条如实交代过的数据/实现边界，用户可能回头再要**：

1. 截断粒度是**整组**，第一组永远整组露出 —— picacg 那种一组塞 20+ 主题的，首屏仍然长。要严格按 8 个入口切就得组内截半（更难读），用户尚未拍。
2. "跨源通用标签"全仓只有 `UnifiedTag` 这一份映射（长篇 / 短篇 / 彩色 / 黑白 / 同人 共 5 个），且某源是否露出取决于它的分类里有没有匹配别名 —— 多数源只有 2–4 个药丸。这是数据边界，不是实现保守；想要更丰富就得先建跨源标签映射表。
3. 原 spec 里"更多分类进入**完整分类页**"没有对应页面（`CategoriesRoute` 早已重定向到探索页），所以实现成页内展开/收起。
