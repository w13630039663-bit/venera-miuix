- `settings-audit-2026-09.md`（仓库根目录）— 设置树全量审计：每个设置项的 file:line、写了哪个键、被谁消费，并区分三类问题（隐形缺口 / 僵尸键 / 名不副实文案）。改或加设置项前先看它，配合 [[project-settings-placeholder-policy]] 的灰行判据。
- `comic-detail-polish-2026-09.md`（仓库根目录）— 漫画详情页本轮视觉打磨的 Scope 与决策记录。**再动详情页前先看**：§2 记了「标签分组名翻译不走 `JsComicSource.translate()`」的否决理由（多语言文档 §1.3 + 保护域），§4 记了两项**已明确暂缓**的美化（预览 3 列网格改横向 LazyRow = 偏离官方；封面衍生主色 Hero 背景 = 仓库无调色板基础设施且官方无此效果），别当新点子重新提。§3.2 记了预览加载最终口径是「固定灰底 + 流光骨架 + 200ms 淡入」，**封面模糊底已被用户要求删除**。
- `large-screen-adaptation-2026-09.md`（仓库根目录）— 大屏（Pixel Tablet 1280dp）三项适配的方案与实测：§一 是从 `master` 抄下来的权威数值表（brief 220dp 一列 / detailed 360dp 一列 / 预览 200dp 一档 / 底栏 `min(540, 宽-24×2)` / Rail 72·224），§五 记**已否决的 B 方案 = 左侧 NavigationRail**（要打穿 `bottomBarClearance` 的 23 处 13 文件契约 + 保护域 `Navigation.kt`，本轮不做），§六 是逐文件落地表，§七 记模拟器实测与一处**我自己写错的结论**（"液态玻璃天然满宽不受影响" —— 它其实会打破 `Navigation.kt` 自己承诺的"两条底栏路径几何零差异"）。**再动列数或底栏宽度前先看它**，尤其别把列数口径从 policy 里拆出去各页自算一份。

- `tag-statistics-port-2026-09.md`（仓库根目录）— 标签统计从 `master`（用户 Flutter fork）移植的决策与实测记录。**再动标签统计/题材归一化前先看**：§1.2 记了 compose 侧「假活」链路的现场证据，§1.3 记了简繁表实测（见 [[project-opencc-table-already-shipped]]，**那份文档里「无转换表所以实现不了」的旧说法已被推翻**），§2 是 D1~D5 的编号决策，§3 列了**移植时故意改掉的原版缺陷**（标签云只带中文显示名 → 原生标签源搜不到；`_secondsPerPage=15` 拍脑袋估时长 → 我们有真实 `duration_seconds`），§4/§7 记了「不带 namespace 的裸标签不参与统计」是照搬的原版口径而不是 bug、以及**不做数据迁移**的理由（tags 列此前从无写入者）。

**How to apply:** 任何 Venera UI 任务开始前读上面这几份确认 scope 与冻结状态；对已冻结页面只允许修实际 Bug 或明确回归，不做顺手视觉/架构重构。Build QA 必须实跑 `:app:compileDebugKotlin`、`:app:testDebugUnitTest`、`:app:assembleDebug` 并在汇报中写明 BUILD SUCCESSFUL；静态检查不能替代真机 QA（设备状况见 [[project-venera-qa-device]]）。**方案文档是这类跨层改动的正式产物**：决策、否决理由与实施偏差都写进对应 md，别让它们只留在对话里。
