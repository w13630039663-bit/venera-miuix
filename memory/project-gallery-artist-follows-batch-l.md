**批次 L 是什么**：画廊侧的「关注画师」系统 —— 详情面板「关于这张图」里每位画师一行（头像 + 平台入口 + 关注），
关注名单存储，首页一栏，以及站别徽标。2026-09-30 全天分 L1~L12 小批做完。
数据面的实测全部记在 [[project-gallery-data-ceilings]] 的「画师外链与头像那一面」两节，这里只记**决策与理由**。

**被同日推翻的一条（最重要）**：L6 那轮拍的是「关注**不进首页，只留入口**」，理由是首页节数不能随数据变
（锚点漂移，见 [[lazy-list-anchor-drift-on-head-insertion]]）。同日 L11 用户直接改令
「首页的收藏里的画师也改成正在关注的画师」→ **推翻成立**，实现方式同时守住了两条：
**空名单时那一节照样在、内容换成一句引导**，所以节数恒定没有被破坏。
⇒ 以后别拿"节数会随数据变"当理由把功能挡在首页外 —— 先想"空态那一节摆什么"，再谈能不能进。
顺带：搜索卡里那行「关注的画师」入口被撤（用户选"撤掉"），理由是**同一份名单在两处长得不一样，读起来像两个功能**。

**首页那一栏的换名史**：它从前就叫「正在关注的画师」，因为"仓库里没有任何关注数据源、那名配不上任何读数"
被改成「收藏里的画师」。批次 L 有了名单存储那名才重新配得上 —— 换名不是审美，是**读数能不能撑住这个名字**。

**其余拍板（用户原话口径）**
- 关注的语义 = **名单 + 直达入口**，不是"这位有几张新图"（没有任何更新来源，那个数只能编）。
- 平台入口用**文字胶囊**（pixiv / X / FANBOX），不往 APK 塞第三方 logo；
  但**站别徽标**那一处用户点名要站方图标 —— 两处不矛盾：一处问"这是谁的什么平台"，一处问"这张图来自哪一站"。
- **元数据一律不落库**：pixiv 用户号与头像 URL 实测会过期，名单只存「站别 + 名字 + 关注时刻」，需要时现取。
- **面板打开才取数**（一位最贵三笔请求），失败只写日志、屏上什么都不摆，且**绝不说"这位没有 pixiv"**。
- 出处（`source`，实测覆盖 18/20）只**补站方没给的那一档**：站方画师记录 > 出处 > 作品页反查出的作者主页；
  同平台不重复摆、上限两枚。
- **pixiv 作品页反查出的作者：照摆，胶囊带账号**（`pixiv tokenbox`）。理由：一致率只有 4/11，
  而分歧大多是同一人换写法 —— 严格判一致会砍掉大多数，不写账号又会让"A 的脸挂在 B 那一行下"静默发生。
- 头像链 `pixiv 用户档 → fanbox iconUrl → Mastodon avatar → 首字母座`，每档只试一次。
  ⚠️ 失败那一路只有日志，而**本机应用日志被压掉**（见 [[project-venera-qa-device]]）⇒ 汇报时别把"加了日志"说成用户能看到原因。
- **yande.re 站别徽标**：知情（它是一张裁自插画的 16px 粉脸、第三方也没有高清档、放大到 24dp 必糊）之后
  用户仍选「摆 16px 脸」，理由：**那就是 yande.re 在浏览器标签页上的标识，与站方一致优先于好看**。
  ⇒ 用户会为了"忠于站方"接受观感退化；我的义务是把代价量出来摆上桌，不是替他守着旧结论。
